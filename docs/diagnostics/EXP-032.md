# EXP-032 — TryCallGuestFunction Return Value Propagation Fix

## Symptom

IL2CPP resolver at 0x804ED9B90 returns 0 for all 232 symbol lookup calls,
preventing Yatzi from booting past IL2CPP initialization.

## Root Cause

`ExecuteGuestThreadEntry` calls `CallNativeEntry(ptr)` which executes the
resolver natively. The resolver returns the correct `func_impl` pointer in
RAX (e.g., `0x804ED85D0` for `il2cpp_init`).

However, `CallNativeEntry` was declared to return `int` (32-bit), truncating
the 64-bit RAX to 32 bits. Additionally, `ExecuteGuestThreadEntry` never wrote
`nativeReturn` back to `CpuContext.Rax`.

`TryCallGuestFunction` then reads `context[CpuRegister.Rax]` (still 0, the
initial value) instead of the actual return value.

## Evidence

```
[EXP032-NATIVE] nativeReturn=0x04ED85D0 contextRax=0x0000000000000000
```

After fix:
```
[EXP032-ABI-AFTER] nativeReturn=0x0000000804ED85D0 contextRax=0x0000000804ED85D0
[RESOLVER-TRACE] Exit #1: RAX=0x0000000804ED85D0 (non-zero)
```

## Fix

Two changes in `DirectExecutionBackend.cs`:

1. Change `CallNativeEntry` return type from `int` to `long`:
```csharp
private unsafe static long CallNativeEntry(void* entry)
{
    var nativeEntry = (delegate* unmanaged[Cdecl]<long>)entry;
    return nativeEntry();
}
```

2. Write `nativeReturn` to `CpuContext.Rax` after `CallNativeEntry` returns:
```csharp
var nativeReturn = CallNativeEntry(ptr);
context[CpuRegister.Rax] = (ulong)nativeReturn;
```

Also updated callers in `DirectExecutionBackend.NativeWorker.cs` and the
main entry point (`num6` changed from `int` to `long`).

## Regression Test

After fix:
- 232/232 resolver calls return non-zero ✅
- All func_impl values match expected (e.g., 0x804ED85D0 for il2cpp_init) ✅
- 64-bit return value preserved (no truncation) ✅
- Game progresses past IL2CPP init to next blocker ✅
- NULL execute faults reduced from 1004 to 1005 (unchanged — unrelated) ✅
