# EXP-083 — Metadata Global 0x801E51240 Never Populated

**Identity:** Yatzi / PPSA17697 / verified
**Configuration:** `SHARPEMU_SEMA_FAST_PATH=0` (proper blocking, no NOP bypass)
**Resumes:** EXP-057 (wrapper-never-called thread, abandoned when EXP-061 found wrong dump)

**Question:** Where should the call to wrapper 0x800805AE0 happen, and why is the metadata registration not completing?

**Answer:** The wrapper at `0x800805AE0` is a `#dllimport:` string parser, NOT `il2cpp_codegen_register` — EXP-052/053 misidentified it. The actual root cause is that the **metadata global at `0x801E51240` is never populated** because `hash_lookup` (`0x8004BD620`) returns NULL, causing the conditional write at `0x8013EF019` to be skipped.

**Confidence:** PROVEN by static analysis (write site disassembly) + runtime evidence (global=NULL in log).

The wrapper's "never called" status is a **red herring** — it's not supposed to be called during normal IL2CPP init. It's only called when processing `#dllimport:` directives in IL2CPP source strings.

## Root Cause

### The metadata global at `0x801E51240` is never populated.

**Evidence:**
- Log: `[0x801E51240] (metadata global) = 0x0000000000000000` (from EXP058-INIT-STATE and EXP038-STATE)
- Log: `EXP038-CRASH_FUNC-STATE: global=0x0000000000000000`

### Why the global is never populated

The ONLY write to `0x801E51240` is at EBOOT address `0x8013EF019`:
```
0x8013EEFE7: call hash_lookup (0x8004BD620)    ← lookup metadata object
0x8013EEFF8: test rax, rax                      ← check result
0x8013EEFFB: je 0x8013EF3C4                     ← if NULL, SKIP the write
0x8013EF019: mov [0x801E51240], rax             ← ONLY reached if hash_lookup returns non-NULL
```

`hash_lookup` (`0x8004BD620`) returns NULL because the IL2CPP metadata hash table is not properly populated. The hash table writer (`0x8007F90A0`) is called once and initializes the global hash table at `0x801EF7610` to `0x600103DB0`, but the metadata entries themselves are empty.

### Connection to EXP-041/042

EXP-041 found "il2cpp_init called BEFORE hash lookup sets 0x801E51240" and EXP-042 found "0x801E51240 needs pre-init" — but these were on the WRONG dump (Dreaming Sarah, not Yatzi). **EXP-083 confirms the SAME issue exists on the CORRECT dump.**

### Connection to EXP-053

EXP-053 found "wrapper 0x800805AE0 never called." EXP-083 corrects this: the wrapper is a `#dllimport:` string parser, not `il2cpp_codegen_register`. The wrapper's "never called" status is expected — it's not part of the normal init path. The real issue is that `hash_lookup` returns NULL, preventing the metadata global from being set.

## Fix Location

**SharpEmu HLE must ensure `hash_lookup` (`0x8004BD620`) returns a valid metadata object.**

The hash table at `0x801EF7610` is initialized (to `0x600103DB0`), but the entries in the hash table are empty (`populated=0/100` from EXP041-CALL7-ENTRIES). This means the IL2CPP metadata registration didn't populate the hash table entries.

The fix requires:
1. **Trace what should populate the hash table entries** — the hash_table_writer (`0x8007F90A0`) is called once but only initializes the table structure, not the entries
2. **Check if a PRX function should insert entries** — the `insert` function at `0x800806940` is callable but only from the `#dllimport:` parser wrapper, which is never called
3. **Check if `il2cpp_codegen_register` (PRX) should call back into EBOOT** to populate the hash table — this is the most likely path

The fix is in **`SharpEmu.HLE/`** — either a missing HLE function that the PRX's `il2cpp_codegen_register` calls back into, or an incorrect return value from an HLE function that causes the registration to skip hash table population.
