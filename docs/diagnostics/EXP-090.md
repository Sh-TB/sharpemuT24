# EXP-090 — Missing Trigger: _ThreadPoolWaitCallback Lookup Returns NULL Due to Empty Hash Table

**Identity:** Yatzi / PPSA17697 / verified
**Configuration:** `SHARPEMU_SEMA_FAST_PATH=0`, metadata at `Media/Metadata/`, EXP-085 flag patch active
**Path:** B (real metadata path)

**Question:** What event should trigger the first IL2CPP ThreadPool work submission?

**Answer:** The missing trigger is the **`_ThreadPoolWaitCallback` function pointer**. The IL2CPP runtime looks up this callback via the metadata hash table during `real_init`, but the lookup returns NULL because the hash table is empty (EXP-040). Without the callback, the ThreadPool cannot dispatch work. **Classification: A) Missing HLE implementation** (metadata hash table not populated).

**Confidence:** PROVEN by static analysis (disassembly of `_ThreadPoolWaitCallback` lookup in `real_init` + connection to EXP-040 hash table findings + EXP-085 flag patch side effect).

---

## Root Cause Chain

```
EXP-040: IL2CPP metadata hash table entries never filled (hash table is empty)
    ↓
EXP-085: Metadata flag patch sets [entry+0x19]=1 → metadata_lookup returns 0 for ALL queries
    ↓
real_init calls 0x804F21D70 to look up "_ThreadPoolWaitCallback" → returns NULL (hash table empty)
    ↓
Global at 0x808B53C48 = NULL → ThreadPool has no worker callback
    ↓
ThreadPool created but can't dispatch work (no callback function)
    ↓
Main thread enters ThreadPool → WaitSema(0x81) → blocks (no work)
    ↓
All 15 threads deadlocked
```

## The _ThreadPoolWaitCallback Lookup

Found in `real_init` (`0x804F04BA0`) at offset `+0x0A36`:

```asm
; Load the type pointer for System.Threading.ThreadPool
0x804F055C1: mov rdi, [rip + 0x3C4E428]   ; type pointer
; Load the namespace string
0x804F055C8: lea rsi, [rip + 0x3367704]    ; namespace string
; Load the method name string
0x804F055CF: lea rdx, [rip + 0x3369D67]    ; "_ThreadPoolWaitCallback"
; Look up the method
0x804F055D6: call 0x804F21D70               ; il2cpp_class_get_method_from_name
; Store the result (function pointer)
0x804F055DB: mov [rip + 0x3C4E666], rax     ; store at global 0x808B53C48
```

If `0x804F21D70` returns NULL (because the hash table is empty), the global at `0x808B53C48` stays NULL, and the ThreadPool has no callback to invoke when work is submitted.

## EXP-085 Side Effect

The EXP-085 metadata flag patch (`[entry+0x19]=1`) was designed to prevent `crash_func` from reading the NULL metadata global at `0x801E51240`. It does this by making `metadata_lookup` (`0x800C66B40`) return 0 immediately (without searching).

**Side effect:** This also prevents ALL other metadata lookups from succeeding, including the `_ThreadPoolWaitCallback` lookup. The lookup function `0x804F21D70` internally calls `metadata_lookup` or a similar hash table search, which returns NULL because:
1. The EXP-085 flag patch makes the metadata list entries non-searchable
2. The hash table entries themselves are empty (EXP-040)

## Classification Correction

EXP-089 classified this as "D) Unity/IL2CPP waiting for an event that SharpEmu never generates."

**Corrected:** **A) Missing HLE implementation** — the IL2CPP metadata hash table is not populated. The metadata registration process (which should fill the hash table with type/method entries) is incomplete. This is the same root cause identified in EXP-040.

## Fix Direction

The fix must address the **root cause**: the IL2CPP metadata hash table is not populated.

### Option 1: Implement IL2CPP metadata registration in SharpEmu HLE
- The PRX's `il2cpp_init` → `real_init` should call a registration function that populates the hash table
- This registration function reads from `global-metadata.dat` and inserts entries into the hash table
- SharpEmu may need to implement or fix an HLE function that this registration depends on

### Option 2: Remove EXP-085 flag patch and fix the underlying crash differently
- The EXP-085 patch was a diagnostic fix for the `crash_func` crash (NULL metadata global at `0x801E51240`)
- If the hash table is properly populated, `metadata_lookup` would return valid results
- The crash_func crash would not occur because `0x801E51240` would be set to a valid value
- The EXP-085 flag patch could then be removed

### Recommended approach:
1. First, investigate WHY the hash table is not populated (EXP-040's finding)
2. Find what PRX function should insert entries into the hash table
3. Determine if a missing SharpEmu HLE function prevents that insertion
4. Fix the HLE function → hash table gets populated → lookups succeed → ThreadPool works
