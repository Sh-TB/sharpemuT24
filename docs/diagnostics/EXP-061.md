## 5. Previous EXP Address Provenance

### Were EXP-035..058 addresses from old or new eboot?

**ALL addresses from EXP-035..058 came from the OLD eboot.bin (Dreaming Sarah, 7.7MB).**

Evidence:
- EXP-035..058 ran against `/tmp/games/yatzi/eboot.bin` which was actually the old 7.7MB file (before the complete dump arrived)
- The old eboot SHA256 (c2712ac3...) matches the dreaming-sarah eboot exactly
- All addresses (0x80135DDD0, 0x80134FA00, 0x804F04BA0, 0x804F23320, 0x801E51240, etc.) were from this wrong eboot

### Are these addresses valid for the new eboot?

**Surprisingly, many addresses appear to work** because:
1. The PRX (Il2cppUserAssemblies.prx) is the SAME file in both cases (it was present in the old incomplete dump too... wait, no — the audit showed it was MISSING from the old dump)

**Actually, correction:** The old dump did NOT have Il2cppUserAssemblies.prx. The old "Yatzi" test was running Dreaming Sarah's eboot.bin (7.7MB, non-IL2CPP) with only libc.prx. All the IL2CPP-related addresses (0x804F04BA0, 0x804F23320, etc. in the PRX address space) could only have come from a run where the PRX was present.

**Wait — this doesn't add up.** EXP-035..058 found IL2CPP functions at 0x804CD5000+ (PRX address space), which means the PRX WAS loaded. But the audit showed Il2cppUserAssemblies.prx was missing from the old upload...

**Resolution:** The old upload at `/tmp/my-project/upload/PPSA02929/PPSA02929-app0/` was missing the PRX, but the actual test runs used files at `/tmp/games/yatzi/` which may have had a different (also incomplete) set of files at that time. The dreaming-sarah eboot was 7.7MB — too small to contain IL2CPP code. The PRX must have been present during EXP-035..058 runs (otherwise il2cpp_init would never have been called).

**Conclusion:** The old test runs used Dreaming Sarah's eboot.bin WITH Yatzi's Il2cppUserAssemblies.prx (a mixed dump). This is why:
- il2cpp_init was called (PRX was present)
- But metadata was missing (global-metadata.dat was absent)
- The crash chain involved both eboot addresses (Dreaming Sarah's code) and PRX addresses (Yatzi's IL2CPP code)

**All EXP-035..058 findings are INVALID for the current Yatzi dump** because:
1. The eboot addresses (0x80135DDD0, 0x80134FA00, 0x801E51240, etc.) are from Dreaming Sarah
2. The PRX addresses (0x804F04BA0, 0x804F23320, etc.) are from Yatzi's PRX but were interacting with Dreaming Sarah's eboot code
3. The struct identifications (Il2CodeGenModule at 0x8086E9000) may be correct for Yatzi's PRX but were analyzed in a mixed context
