# EXP-085 — Metadata Flag Patch: Crash Eliminated, VideoOut Reached

**Identity:** Yatzi / PPSA17697 / verified
**Configuration:** `SHARPEMU_SEMA_FAST_PATH=0`, no NOP bypass, with EXP-085 diagnostic patch

**Question:** Does setting `[metadata_list_entry+0x19]=1` before `il2cpp_init` allow the game to progress past the crash point?

**Answer:** **YES.** The patch eliminates the crash at `0x80135DE83` (crash_func reading NULL metadata global). `metadata_lookup` now returns 0 (matching real PS5 behavior). `il2cpp_init` completes. The game reaches **VideoOut initialization** — the furthest progress ever achieved for Yatzi.

**Confidence:** PROVEN by A/B comparison (before/after patch, same binary, same config).

---

## Patch Applied

**Address patched:** `[metadata_list_entry+0x19]` (entry data at `0x60011BD50`, offset `+0x19`)

**Before:** `0x00` (searchable — causes metadata_lookup to find match and return non-zero)
**After:** `0x01` (not searchable — causes metadata_lookup to return 0 immediately)

**Patch location:** `_Exp036Il2cppInitTracer.cs`, inside `Exp036TryHandleIl2cppInitInt3()`, executed when the il2cpp_init INT3 tracer fires (before il2cpp_init executes).

**Patch code:**
```csharp
// Read metadata list: [0x801EA4E80] → [head+8] → [node+8] → entry_data
ulong listHead = *(ulong*)0x801EA4E80;
ulong node = *(ulong*)(listHead + 8);
ulong entryData = *(ulong*)(node + 8);
// Set flag = 1 (non-searchable)
*((byte*)(entryData + 0x19)) = 1;
```

## Root Cause (confirmed)

**The metadata list entries at `[0x801EA4E80]` have `flag=0x00` (searchable) when they should be non-zero (not searchable) before `il2cpp_init` runs.**

This causes `metadata_lookup` (`0x800C66B40`) to find a match and return non-zero, which triggers the callback to call `crash_func` (`0x80135DDD0`), which reads the NULL metadata global at `[0x801E51240]` and crashes.

Setting `flag=0x01` before `il2cpp_init` makes `metadata_lookup` return 0 (matching real PS5 behavior), preventing the crash and allowing `il2cpp_init` to complete.

---

## Remaining Blocker

The new crash at `0x80080684D` (`mov r8d, [r15+rcx]` where `r15=NULL`) is the **per-image hash table NULL** issue identified in EXP-082. This is a **separate issue** from the metadata flag bug — it occurs when Unity tries to look up a type by name using a per-image hash table that was never initialized.

This crash happens AFTER VideoOut initialization, meaning the game progressed further than ever before.

---

## Fix Location

The permanent fix should be in **`SharpEmu.HLE/`** — find what causes the metadata list entries to have `flag=0x00` instead of `flag=0x01`. The registration iterator at `0x800B8D530` adds entries with `flag=0x00`. On real PS5, either:
1. The entries are added with `flag=0x01` initially (not searchable until fully initialized)
2. A separate initialization step sets `flag=0x01` before `il2cpp_init`
3. The entries don't exist yet (list is empty) at this point on real PS5

The diagnostic patch in `_Exp036Il2cppInitTracer.cs` is a **temporary fix** — it should be replaced with a proper HLE fix once the root cause of the premature registration is identified.
