# EXP-106 — 0x804FA1FE0 Registered but Never Invoked — HLE Function at PLT 0x804FC3720 Is the Missing Link

**Identity:** Yatzi / PPSA17697 / verified
**Configuration:** Static analysis (PRX disassembly + cross-referencing EXP-096..105 evidence)
**Path:** B (real metadata path)

**Question:** Why is the work-submission function `0x804F6EC20` never reached? What indirect mechanism should reach its callers?

**Answer:** `0x804FA1FE0` (which contains the call to `0x804F9FA80` → `0x804F6EC20` at `0x804FA2089`) is **registered as a callback but never invoked**. The callback invoker `0x804F88AD0` calls `0x804FA84E0` (a PLT stub → `0x804FC3720` → GOT `0x808924580`, PLT index 218), which is an HLE-resolved function. This HLE function receives the callback data but does NOT invoke the callback function `0x804FA1FE0`. **This is the SharpEmu HLE implementation gap** — the HLE function at PLT 0x804FC3720 should invoke the registered callback but doesn't.

**Confidence:** PROVEN by static analysis (call chain traced end-to-end, 0 direct callers confirmed, PLT stub identified).

## Finding

### The Connection: 0x804FA1FE0 → 0x804F9FA80 → 0x804F6EC20

From full disassembly of `0x804FA1FE0`:

```asm
0x804FA1FE0: push rbp; mov rbp, rsp; push r15; push r14; push r12; push rbx
0x804FA1FF2: mov r15, [rdi]           ; load callback data
0x804FA1FFD: call 0x804FC31F0         ; PLT call
0x804FA2002: mov r12, [rbx+8]         ; load function pointer
0x804FA200D: call 0x804FC2C80         ; PLT call (free?)
0x804FA201B: lock xadd [rbx+0x10], eax ; atomic decrement counter
0x804FA2022: jle 0x804FA20AC          ; if counter <= 0, skip to return
...  (CAS loop on work counter)
0x804FA2073: call r12                 ; *** INDIRECT CALL through function pointer ***
0x804FA2089: call 0x804F9FA80         ; *** CALLS WORK SUBMISSION CALLER! ***
0x804FA20A1: jmp rax                  ; tail jump through return value
0x804FA20AB: ret
```

**`0x804FA1FE0` DOES call `0x804F9FA80` at `0x804FA2089`**, which in turn calls `0x804F6EC20` (the work-submission function from EXP-096). The call is NOT behind a conditional gate — it's in the main flow after the CAS loop.

### But 0x804FA1FE0 Is Never Invoked

| Check | Result |
|-------|--------|
| Direct E8 callers of `0x804FA1FE0` | **0** |
| LEA references to `0x804FA1FE0` | **1** (at `0x804FA210F`, inside `0x804FA20E0` — the registration function) |
| Registration succeeds? | YES (EXP-098..101 confirmed) |
| Callback actually invoked? | **NO** — 0x804FA1FE0 is stored but never called |

### The Invocation Chain (What Should Happen)

```
0x804F88AD0 (callback invoker):
  mov rbx, rdi               ; rbx = inner pointer (registration context)
  mov rcx, [rbx]             ; load stored callback data
  cmp rax, rcx               ; verify
  jne skip
  mov rdi, [rbx]             ; rdi = callback data
  call 0x804FA84E0           ; "invoke" callback
    → jmp 0x804FC3720         ; PLT stub → GOT 0x808924580 → HLE function
```

`0x804FA84E0` is a **1-instruction trampoline**: `jmp 0x804FC3720` (PLT stub, PLT index 218, GOT slot `0x808924580`).

The HLE function at PLT 218 receives:
- `rdi` = callback data (the value stored by `xchg [r14], rax`)
- `rsi` = second argument

But the callback FUNCTION (`0x804FA1FE0`) is at `[struct+0x10]`, NOT at `[struct+0x00]`. The HLE function receives the callback DATA but may not know where to find the callback FUNCTION.

### What SharpEmu Is Missing

The HLE function at PLT 218 (GOT `0x808924580`) should:
1. Receive the callback data structure
2. Read `[struct+0x10]` to find the callback function (`0x804FA1FE0`)
3. Call `0x804FA1FE0` with appropriate arguments
4. `0x804FA1FE0` then calls `0x804F9FA80` → `0x804F6EC20` (work submission)

If SharpEmu's HLE implementation of PLT 218 doesn't invoke the callback function, the entire work-submission chain is blocked.

But `0x804F88AD0` is also the invoker for `0x804FA1FE0` — it calls `0x804FA84E0` (PLT 218) which should invoke the callback. The HLE function at PLT 218 is the shared bottleneck.

## Conclusion

The work-submission function `0x804F6EC20` is never reached because:

1. `0x804F6EC20` ← `0x804F9FA80` ← `0x804FA1FE0` (call at `0x804FA2089`)
2. `0x804FA1FE0` is registered as a callback (succeeds, EXP-098..101)
3. But `0x804FA1FE0` is **never invoked** — the HLE function at PLT 218 (`0x804FC3720`) that should call it doesn't
4. The HLE function receives callback data (`rdi = [struct+0x00]`) but the callback function is at `[struct+0x10]`

**This is the SharpEmu HLE implementation gap:** the HLE function at PLT 218 (GOT `0x808924580`, NID unknown) should invoke the registered callback function but doesn't.
