# EXP-051 — Combined Fixes Investigation (Buffer + NOP Jumps + Loop Fix)

## Date: 2026-07-30
## Status: COMPLETE — All three approaches tested, buffer fix causes new crashes

---

## Executive Summary

Tested three combined fixes:
- **A: 64KB buffer** for 950 metadata fields → causes new NULL reads by changing control flow
- **B: NOP 12 conditional jumps** → forces code through paths that read NULL string pointers
- **C: Break probe loop** at `0x800806854` → prevents infinite SIGSEGV loop

All three were tested individually and in combination. **None achieve the goal.**
Setting metadata fields to non-NULL values prematurely changes the init function's
control flow, exposing MORE NULL reads (string pointers, other globals). NOPping
protective jumps forces code through paths that were meant to be skipped.

**Only the callback stub (EXP-048) remains as a working fix.**

### Key finding
Setting metadata fields to non-NULL values **prematurely changes control flow**:
- Code interprets non-NULL as "metadata ready"
- Takes paths that read string pointers and other globals
- These are ALSO NULL → new SIGSEGVs

The init function's control flow is designed to SKIP these reads when metadata
is NULL. Setting metadata to fake non-NULL values defeats this protection.

---

## Why Hash Lookup Never Fires

The hash lookup at `0x8013EEFE0` is protected by 15+ conditional jumps that
check metadata readiness. These jumps are **protective** — they prevent reading
uninitialized metadata. On SharpEmu, metadata is not ready, so the jumps skip
the hash lookup.

NOPping the jumps forces code through unprotected paths → new crashes.
Setting metadata to fake values makes the jumps not taken → same result.

**The only way to make the hash lookup run is to have REAL metadata ready.**
This requires the PS5 pre-init mechanism that SharpEmu doesn't implement.

---

## Fatal Loop at 0x80080684D

The probe loop fix (C) was tested in Run 1. NOPping the `jne` at `0x800806854`
breaks the infinite loop. But without the buffer fix (A), the loop doesn't
occur (the crash is elsewhere). With the buffer fix (A), the loop occurs but
breaking it just moves the crash to a different location.

The loop fix is a **safety net** for future experiments but doesn't solve
the fundamental issue.

## Next Step (EXP-052)

The investigation has reached the limits of patching. The fundamental issue is:

**SharpEmu doesn't implement the PS5 pre-init mechanism that sets metadata
fields before il2cpp_init. Without this mechanism, the init function's
protective jumps skip the hash lookup, and all metadata stays NULL.**

### Recommended approach:
1. **Implement the missing PS5 pre-init mechanism** — this is the only
   real fix. The mechanism likely involves:
   - PS5 SDK runtime initialization (before user code)
   - Dynamic linker metadata resolution
   - Module start callback (not DT_INIT, but a separate PS5 mechanism)

2. **Alternative: implement il2cpp_codegen_register** — this is the Unity
   function that registers metadata. It's called during il2cpp_init but
   might be skipped on SharpEmu due to the callback stub.

3. **Alternative: implement the hash table fill function** — find the
   function that fills the hash table at `0x801EF7610` and call it
   manually before il2cpp_init.
