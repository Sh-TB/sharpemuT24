## User Feedback Resolution

### #1: Reconcile EXP-075 vs EXP-076

**Both are correct and complementary:**
- EXP-075: CLEAR function (0x800A9F750) clears [rbx+0x108] to 0 — this is the MECHANISM
- EXP-076: [rbx+0x108] points to previous worker's descriptor — this is the IDENTITY

The tagged pointer at [rbx+0x108] is a chain dependency: Worker N depends on Worker N-1. The SET function writes the tagged pointer (dependency established); the CLEAR function writes 0 (dependency resolved). CLEAR should fire when the previous worker completes its task.

Both workers can't complete because [rbx+0xf8]=NULL (no task function), so CLEAR never fires.

### #2: Is GPU init the prerequisite?

**NO — GPU init is NOT the direct blocker.**

The main thread progresses PAST worker creation and reaches:
1. il2cpp_init (second call)
2. real_init
3. Call #7 (metadata consumer)
4. Array processor
5. sceKernelAllocateDirectMemory (GPU memory allocation — this IS called!)
6. **Then stalls on WaitSema in PRX code**

The game never reaches sceVideoOutOpen, but that's because the main thread stalls on a **semaphore wait** in the PRX BEFORE reaching the GPU init code. The stall is the same class of bug (semaphore never signaled), not a missing GPU HLE function.

### #3: Trace backward from PRX write sites

The 170 PRX write sites for [reg+0xf8] are at addresses like 0x804E5F571. The main thread stalls at 0x804F6E9EB (WaitSema in PRX). The stall is a **semaphore wait** — the same class of bug as the worker stall, just at a different point in the PRX code.

The main thread is spinning on WaitSema/SignalSema in the PRX (30M+ imports), never reaching the task dispatch code that would write [rbx+0xf8].

## Root Cause (Corrected)

**EXP-076's "missing GPU init" conclusion was WRONG.** The main thread DOES reach GPU memory allocation (sceKernelAllocateDirectMemory). The stall is NOT because GPU init is missing — it's because the main thread is stuck in a **semaphore spin** in the PRX code after allocating GPU memory.

The root cause is the **same class of bug** as all previous stalls: the PRX is waiting on a semaphore that nobody signals (or with FAST_PATH=1, spinning in a WaitSema/SignalSema loop without making progress).
