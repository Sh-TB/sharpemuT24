**Path:** B (real metadata path)

**Question:** What indirect call mechanism should reach the work-submission function `0x804F6EC20`, and why is the function pointer never set?

**Answer:** The 5 dead-code function addresses (including the work-submission function `0x804F6EC20`) are **NOT registered as function pointers anywhere** — not in static data segments, not in runtime-set globals, not in init/fini arrays, and not via LEA/movabs instructions (except one self-referential LEA). The self-registering function `0x804FA1FE0` (which loads its own address and tail-jumps to the registration function `0x804F889D0`) is itself dead code with 0 callers. The once-init guard `[0x808B418D8]` remains at `0xFFFFFFFFFFFFFFFF` (sentinel — never cleared), confirming the registration never runs.

**Confidence:** PROVEN by exhaustive static search + runtime dump of all function pointer globals.

## The Self-Registering Function Pattern

Function `0x804FA1FE0` is a **self-registering function**:

```asm
0x804FA2108  mov  rcx, [rip+0x3b9f7c9]  ; -> 0x808B418D8 (once-init guard)
0x804FA210F  lea  rsi, [rip+...]        ; -> 0x804FA1FE0 (its own address!)
0x804FA2116  mov  rdx, rax
0x804FA2119  mov  rdi, [r15+0x8]
0x804FA211D  add  rsp, 0x8
0x804FA2121  pop  rbx
0x804FA2122  pop  r14
0x804FA2124  pop  r15
0x804FA2126  pop  rbp
0x804FA2127  jmp  0x804F889D0           ; tail jump to registration function
```

It loads its own address into `rsi`, loads the once-init guard into `rcx`, and tail-jumps to `0x804F889D0` (the registration function). The registration function `0x804F889D0` reads `[0x808923D88]` (the IL2CPP context) and stores `rsi` (the function pointer) into a registration structure.

**But `0x804FA1FE0` itself has 0 callers** — it's dead code. So the registration never happens.

## What Should Call 0x804FA1FE0?

The self-registering function `0x804FA1FE0` must be called by something. Candidates:
1. **DT_INIT_ARRAY entry** — the PRX's init_array (constructors) should include `0x804FA1FE0`. But the fini_array (checked at runtime) doesn't contain it, and the init_array hasn't been explicitly checked yet.
2. **C++ static constructor** — a global C++ object's constructor calls `0x804FA1FE0` during initialization.
3. **IL2CPP icall registration** — `il2cpp_add_internal_call` or similar runtime registration calls `0x804FA1FE0`.
4. **A function called from `real_init`** — one of the 25 call sites in `real_init` (`0x804F04BA0`) might eventually reach `0x804FA1FE0` via a longer call chain.
