# EXP-037 — IL2CPP Global State Initialization Investigation

## Date: 2026-07-30
## Status: COMPLETE — Root cause identified, no fix applied yet

---

## Executive Summary

The crash at `0x80135DE83` (`mov ecx, [rax+0x98]` where `rax=0`) is caused
by an uninitialized IL2CPP metadata global pointer at `0x801E51240`.

The global should be set by a hash table lookup in function `0x8013EB6B0`,
but the hash table at `0x801EE7610` is empty (BSS, zero-initialized).

The hash table should be populated by IL2CPP static initializers (995
`il2cpp_add_internal_call` registration sites), but **both eboot.bin and
Il2cppUserAssemblies.prx have empty `DT_INIT_ARRAY` sections** — the
static initializers are never called.

---

## Task 1 — Identify the Global

### Global address
```
Instruction: 0x80135DE6D: mov rax, [rip + 0xaf33cc]
RIP after:   0x80135DE74
Global addr: 0x80135DE74 + 0xAF33CC = 0x801E51240
```

### Segment location
- PH[7]: vaddr `0x1D20000`, filesz `0xD5D78`, memsz `0x219970`
- Global vaddr `0x1E51240` is in **BSS** (beyond filesz, zero-initialized)
- File has no relocation for this address — starts as 0 at runtime

### References found
25 RIP-relative references to `0x801E51240` in eboot.bin:

| Address | Instruction | Type |
|---------|-------------|------|
| `0x80135DE6D` | `mov rax, [rip+0xaf33cc]` | READ (crash site) |
| `0x8013EF019` | `mov [rip+0xa62220], rax` | **WRITE** (only write) |
| `0x8007FD752` | `cmp [rip+0x1653ae7], rdi` | CMP |
| `0x8007FD8EC` | `cmp [rip+0x165394d], rdi` | CMP |
| `0x800AABD42` | `mov rax, [rip+0x13a54f7]` | READ |
| ... | (20 more reads) | READ |

### Structure layout
The global points to a metadata structure with fields at:
`+0x40`, `+0x80`, `+0x90`, `+0x98`, `+0xa0`, `+0xd0`, `+0xd3`, `+0xd5`, `+0xdc`

This is consistent with an IL2CPP metadata registration structure.

## Task 2 — Trace Initialization APIs

### il2cpp_init call tracing
- INT3 patched at `0x804ED85D0` (il2cpp_init entry)
- **il2cpp_init IS called** from `0x8013ED05D` (tid=4, main thread)
- The call uses `call [rip+0xae92c3]` → `call [0x801ED6320]` → `call il2cpp_init`
- `0x801ED6320` is `global[0]` in the IL2CPP API table

### il2cpp_init internals
```
il2cpp_init (0x804ED85D0):
  call 0x804fc2f40    ; some setup
  call 0x804f04ba0    ; real init (the large function)
  ret
```

The real init (`0x804f04ba0`) calls many sub-functions including metadata
registration. One of these calls back into eboot.bin at `0x80135DDD0`,
which reads the global at `0x801E51240`.

### Call chain
```
Entry (0x800000070)
  → 0x8013FCE40 (main function)
    → 0x8013EB6B0 (init function — contains BOTH the WRITE and il2cpp_init call)
      → hash lookup at 0x8004BD620 (FAILS — hash table empty)
      → [WRITE at 0x8013EF019 SKIPPED because lookup returned 0]
      → call il2cpp_init at 0x8013ED057
        → il2cpp_init calls back into eboot.bin
          → 0x80135DDD0 reads global at 0x801E51240
          → global is 0 → CRASH at 0x80135DE83
```

## Task 3 — Function Table Routing

### IL2CPP API table (at `0x801ED6320`)
- 232 entries, all resolved to real func_impl addresses in `Il2cppUserAssemblies.prx`
- `global[0]` = `0x804ED85D0` = `il2cpp_init` ✓
- `global[12]` = `0x804ED8770` = `il2cpp_add_internal_call` ✓

### Call site analysis
- 1 call to `global[0]` (il2cpp_init) at `0x8013ED057`
- 995 calls to `global[12]` (il2cpp_add_internal_call) — ALL before il2cpp_init
- All func_impls are real PRX addresses (no fake stubs)

**Function table routing is CORRECT.** No fake stubs remain.

## Task 4 — PRX/Static Initialization

### eboot.bin
```
DT_INIT = 0x10 (function at 0x800000010)
DT_INIT_ARRAY = 0x0 (NONE)
DT_INIT_ARRAYSZ = 0x0
DT_PREINIT_ARRAY = 0x7 (invalid, size=0)
```

The `DT_INIT` function at `0x800000010` iterates an init_array:
- Start: `lea rbx, [rip+0x52]` → `0x800000070` (entry point address!)
- End: `[0x801D1A588]` = `0x800000070` (RELATIVE reloc, addend 0x70)
- Start == End → **0 entries** → loop skipped

### Il2cppUserAssemblies.prx
```
DT_INIT = 0x10 (function at 0x804CD5010)
DT_INIT_ARRAY = 0x0 (NONE)
DT_INIT_ARRAYSZ = 0x0
```

Same pattern: PRX DT_INIT iterates an empty init_array.

### 995 il2cpp_add_internal_call sites
- Located at addresses like `0x80045C2F3`, `0x80045C851`, etc.
- Inside functions like `0x80045C210` — **zero callers found**
- These are static initializer functions that SHOULD be in the init_array
- But the init_array is empty, so they NEVER run

### Conclusion
**Both modules have genuinely empty init_arrays.** The IL2CPP static
initializers (icall registrations, metadata table population) are never
executed. This is the root cause.

## Task 5 — Trace Writes to the Global

### WRITE site
- Address: `0x8013EF019` (`mov [rip+0xa62220], rax`)
- Inside function: `0x8013EB6B0`
- The write stores `rax`, which comes from `call 0x8004BD620` (hash lookup)

### Hash lookup function (0x8004BD620)
```
mov rdx, [rip + 0x1a39fda]  → rdx = [0x801EE7610] (hash table pointer)
test rdx, rdx
je return_0                  → if hash table is NULL, return 0
```

The hash table pointer at `0x801EE7610` is in BSS (zero-initialized).
It is **never set** because the static initializer that should populate it
never runs.

### INT3 watchpoint result
```
[EXP037-WATCHPOINT] WRITE site at 0x8013EF019 patched
[EXP037-GLOBAL] 0x801E51240 = 0x0 (at watchpoint install)
```
The WRITE site INT3 was **never triggered** — the write never executes
because the hash lookup always returns 0 (table is empty).

## Root Cause

The IL2CPP runtime depends on static initializers to:
1. Register 995 internal calls via `il2cpp_add_internal_call`
2. Populate the metadata hash table at `0x801EE7610`
3. Set metadata global pointers like `0x801E51240`

These static initializers are inside functions that have **zero callers**
and are **not in any init_array**. Both eboot.bin and Il2cppUserAssemblies.prx
have `DT_INIT_ARRAY = 0` (empty).

On a real PS5, these initializers are likely triggered by a mechanism that
SharpEmu does not implement — possibly:
- PS5 dynamic linker scans for registration symbols
- The `DT_INIT` function has a different init_array on real hardware
- A PS5-specific runtime hook calls the registration functions

## Next Blocker

The IL2CPP static initializers need to be executed. Possible approaches:

1. **Find the real init_array mechanism**: The PS5 dynamic linker may use
   a different mechanism to discover and run static initializers. Investigate
   PS5 SDK documentation or reverse-engineer the real PS5 linker behavior.

2. **Scan for registration functions**: The 995 `il2cpp_add_internal_call`
   call sites are inside functions with a common pattern. SharpEmu could
   scan for these patterns and call the containing functions.

3. **Hook il2cpp_init**: Instead of running static initializers, hook
   `il2cpp_init` to manually populate the metadata hash table and global
   pointers before il2cpp_init's internal callbacks fire.

4. **Check PS5-specific dynamic entries**: The ELF has PS5-specific
   `DT_SCE_*` entries that SharpEmu may not fully process. One of these
   might point to the real init_array.

### Recommended next step (EXP-038)
Investigate the `DT_SCE_RELA` section (`0x6100003F` at value `0x3900`).
This PS5-specific relocation section may contain the init_array entries
that standard ELF parsing misses. Also check if the `DT_INIT` function's
init_array bounds are set by a PS5-specific relocation that SharpEmu
doesn't apply.
