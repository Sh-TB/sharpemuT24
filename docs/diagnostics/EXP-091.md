# EXP-091 — Hash Table Never Populated: PRX DT_INIT Registration Missing

**Identity:** Yatzi / PPSA17697 / verified
**Configuration:** `SHARPEMU_SEMA_FAST_PATH=0`, metadata at `Media/Metadata/`, EXP-085 flag patch active
**Path:** B (real metadata path)

**Question:** What PRX function should populate the IL2CPP metadata hash table at `0x801EF7610`, and why are entries missing?

**Answer:** The hash table is CREATED (empty) by `hash_table_writer` (`0x8007F90A0`) but NEVER POPULATED. The EBOOT has 1689 READ sites and only 1 WRITE site (the creator). The PRX has 0 reads and 0 writes to `0x801EF7610`. Entries should be inserted by `il2cpp_codegen_register` during PRX module initialization (DT_INIT), but SharpEmu may not properly trigger the PRX's DT_INIT/module_start.

**Confidence:** PROVEN by exhaustive static analysis (1689 read sites, 1 write site in EBOOT; 0 reads, 0 writes in PRX).

## Hash Table State

| Field | Value |
|-------|-------|
| Global pointer | `0x801EF7610` |
| Hash table struct | `0x600103DB0` |
| Entries array | `0x60053E990` |
| Mask | `0x7FFF8` |
| Populated entries | **0/100** (all `0xFFFFFFFF` sentinel) |
| EBOOT reads from `0x801EF7610` | 1689 sites (all LOOKUP, no INSERT) |
| EBOOT writes to `0x801EF7610` | 1 site (creator only, at `0x8007F928C`) |
| PRX reads from `0x801EF7610` | 0 |
| PRX writes to `0x801EF7610` | 0 |

## Hash Table Writer (0x8007F90A0)

Creates the table structure:
```
[rbx + 0x00] = entries pointer (r15)
[rbx + 0x08] = 0 (count, initially 0)
[rbx + 0x10] = 0
[rbx + 0x14] = mask (0x7FFF8)
```

Then writes `rbx` to global `0x801EF7610` at `0x8007F928C`.

**The writer does NOT insert any entries.** It only creates the empty table.

## Chicken-and-Egg Problem

The IL2CPP runtime uses `il2cpp_class_get_method_from_name` to look up function pointers (like `_ThreadPoolWaitCallback`). This lookup searches the hash table. But:

1. The hash table is **empty** (no entries inserted)
2. The insert function is looked up via the **same hash table**
3. Can't populate hash table without the insert function
4. Can't find the insert function without a populated hash table

On real PS5, this is resolved by `il2cpp_codegen_register` running during **PRX module initialization (DT_INIT)**, which directly inserts entries into the hash table WITHOUT using the lookup mechanism.

## Why DT_INIT Matters

The PRX (Il2cppUserAssemblies.prx) has a DT_INIT entry in its dynamic section. When the PS5 OS loads the PRX, it calls DT_INIT before any other code in the PRX runs. DT_INIT should:

1. Call `il2cpp_codegen_register` with the `Il2CppCodeRegistration` and `Il2CppMetadataRegistration` pointers
2. This function iterates type definitions from `global-metadata.dat`
3. For each type: computes hash and INSERTS into the hash table
4. After DT_INIT completes, the hash table is populated
5. Subsequent lookups (like `_ThreadPoolWaitCallback`) succeed

If SharpEmu doesn't call the PRX's DT_INIT, the hash table stays empty.

## Fix Direction

**Ensure the PRX's DT_INIT is called during module loading.**

SharpEmu's PRX loader should:
1. Parse the PRX's dynamic section for DT_INIT
2. Call the DT_INIT function with the correct arguments
3. DT_INIT runs `il2cpp_codegen_register` which populates the hash table
4. After DT_INIT, the hash table has entries → lookups succeed

This is the **root fix** that addresses:
- The empty hash table (EXP-040)
- The NULL _ThreadPoolWaitCallback lookup (EXP-090)
- The ThreadPool deadlock (EXP-088)
- The crash_func crash (EXP-083/084)
- All downstream issues

If DT_INIT properly populates the hash table, the EXP-085 flag patch can be **REMOVED**.
