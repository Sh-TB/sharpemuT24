**Format decoded:**
- `DT_SCE_INIT_ARRAY` = `(dependency_index << 48) | count_or_offset`
  - dependency_index = 0x000A (10 = PRX itself)
  - count_or_offset = 0x000000000001 (1 entry)
- `DT_SCE_INIT_ARRAYSZ` = `(dependency_index << 48) | size`
  - size = 0x09 (9 — could be 9 entries or 9 bytes)

### Task 2: PRX Module Dependencies (PT_SCE_DYNLIBDATA2)

The PRX lists these CRT and library modules:
1. `crti:` — CRT init (provides _init function)
2. `crtbeginS:` — CRT begin shared (provides constructor registration)
3. `libSceSfmt607:` — Sony format library
4. `crtendS:` — CRT end shared
5. `crtn:` — CRT native (provides _fini function)
6-10. Various `lib*_stub_weak:` modules

The CRT modules (`crti`, `crtbeginS`, `crtendS`, `crtn`) are essential for C++ constructor execution. They provide the init_array infrastructure.

### Task 3: SharpEmu's Current Handling

- Parses `DT_INIT_ARRAYSZ` (0x1B) → value is 0 → size is 0
- Does NOT parse `DT_SCE_INIT_ARRAY` (0x61000017) — **IGNORED**
- Does NOT parse `DT_SCE_INIT_ARRAYSZ` (0x61000019) — **IGNORED**

### Task 5: IL2CPP Init Flow (from Katy's blog)

```
Module load:
  1. CRT modules loaded (crti, crtbeginS, etc.)
  2. Init_array constructors executed:
     → s_Il2CppCodegenRegistration() registered via
       RegisterRuntimeInitializeAndCleanup()
  3. DT_INIT (module_start) executed

il2cpp_init():
  → ExecuteInitializations() iterates registration table
  → calls s_Il2CppCodegenRegistration()
  → calls il2cpp_codegen_register(&g_CodeRegistration, &g_MetadataRegistration, &options)
  → IL2CPP runtime fully initialized
```

## Root Cause Confirmation

**SharpEmu does NOT parse `DT_SCE_INIT_ARRAY` (0x61000017) and `DT_SCE_INIT_ARRAYSZ` (0x61000019).**

The PRX has constructor functions (at least 1 entry) that should be called during module load. These constructors register `s_Il2CppCodegenRegistration` with the `RegisterRuntimeInitializeAndCleanup` table. Without calling these constructors:
- The registration table is empty
- `il2cpp_init` → `ExecuteInitializations()` does nothing
- `il2cpp_codegen_register` is never called
- `g_CodeRegistration` and `g_MetadataRegistration` are never set
- IL2CPP runtime is not fully initialized
- `[0x801E51240]` (Il2CppClass*) stays NULL
- Crash at `[NULL+0x98]`

### Answer: D) SharpEmu IL2CPP implementation is incomplete

The IL2CPP implementation itself is not the problem — the real `il2cpp_init` runs natively. The problem is that **SharpEmu doesn't execute the PRX's constructor functions** (from Sony-specific init_array), so the IL2CPP runtime registration never happens.

## Recommended Fix

1. Add constants for Sony-specific init_array tags:
```csharp
private const long DtSceInitArray = 0x61000017;
private const long DtSceInitArraySize = 0x61000019;
```

2. Parse `DT_SCE_INIT_ARRAY` and `DT_SCE_INIT_ARRAYSZ` in the dynamic section parser

3. Decode the packed format:
   - High 16 bits: dependency index (0x000A = PRX itself)
   - Low 48 bits: count or offset

4. Find the actual init_array data (may be in a specific segment or at a computed address)

5. Call the constructor functions during module load (before DT_INIT)

6. This will populate the RegisterRuntimeInitializeAndCleanup table

7. When `il2cpp_init` is called, `ExecuteInitializations()` will work correctly
