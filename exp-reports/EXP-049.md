# EXP-049 — IL2CPP Metadata Initialization Gap Investigation

## Date: 2026-07-30
## Status: COMPLETE — Root cause confirmed as systemic pattern, not one-off

---

## Executive Summary

Identified the NULL pointer at `0x8014327CF`: it reads `[rdx + rsi + 0xd4]`
where `rdx = [0x801E51220]` (NULL). This is the **same class of bug** as
`0x801E51240` — both are fields in the metadata structure at `[0x801E50E40]`,
zeroed by the once-init callback, set by the hash lookup AFTER `il2cpp_init`.

**255 eboot.bin references** to the metadata struct range (`0x801E51000`–
`0x801E54700`) were found. Setting them all to the struct base caused a
**different crash** — the code interpreted the struct as a hash table,
causing an infinite SIGSEGV loop at `0x80080684D`.

The investigation confirms: **this is a systemic pattern**, not a one-off.
il2cpp_init reads many metadata fields that are zeroed by once-init and set
by the hash lookup (which runs AFTER il2cpp_init). On real PS5, these reads
don't happen because the callback (which triggers them) is not called.

## Task A — NULL Pointer Identification

### Crash instruction
```asm
0x8014327B7: mov rax, [0x801E9B940]     ; rax = global
0x8014327BE: mov rdx, [0x801E51220]     ; rdx = metadata field (NULL!)
0x8014327C5: mov esi, [rax + 0xd8]      ; esi = count
0x8014327CB: shl rsi, 4                  ; rsi = offset
0x8014327CF: cmp [rdx + rsi + 0xd4], 2  ; CRASH — rdx=NULL
```

### Source of NULL
`rdx = [0x801E51220]` — a field at offset `+0x3E0` within the metadata
structure at `[0x801E50E40]`. The structure is zeroed by the once-init
callback (`0x8007EB180`). The field is set by the hash lookup at
`0x8013EEFE7` (AFTER `il2cpp_init`).

### Same class as 0x801E51240
- `0x801E51220` = struct+0x3E0 (new crash)
- `0x801E51240` = struct+0x400 (previous crash)
- Both in the same 0x3878-byte structure
- Both zeroed by once-init
- Both set by hash lookup after il2cpp_init

## Task B — Pattern Confirmation

### Metadata struct references
- **255 eboot.bin references** to range `0x801E51000`–`0x801E54700`
- **0 PRX references** to this range (PRX doesn't directly access these globals)
- The reads are all from eboot code called during il2cpp_init

### Common gating callback
The callback `0x80134FA00` (stubbed in EXP-048) was the original gating
mechanism. With it stubbed, il2cpp_init progresses to code that reads
OTHER metadata fields (0x801E51220 etc.). These reads are gated by
different code paths within il2cpp_init, not by a single callback.

### Hash lookup would fix it
The hash lookup at `0x8013EEFE7` sets BOTH `0x801E51220` and `0x801E51240`
(among others). If il2cpp_init could return, the hash lookup would run and
set all the metadata fields. But il2cpp_init crashes before returning.

## Task C — Fatal Crash at 0x80080684D

### Disassembly
```asm
0x80080684D: mov r8d, [r15 + rcx]     ; hash table probe
0x800806851: cmp r8d, r9d             ; compare
0x800806854: jne 0x800806830          ; not equal → next entry
```

### Why non-recoverable
The SIGSEGV recovery sets the destination register to 0 and advances RIP.
But the next instruction (`cmp r8d, r9d`) doesn't fault — it compares 0
with r9d. If not equal (which it isn't), it jumps back to `0x800806830`
which loads the NEXT entry. The next entry also faults (different address
in the 0x0246C000 range). This creates a **tight loop** of SIGSEGVs that
never terminates.

The fault addresses (`0x0246C2A0`, `0x0246C000`, `0x0246C0E0`, etc.)
are in an unmapped region. The table base (`r15`) points to invalid memory.

### Root cause of the loop
When metadata fields are set to `0x801E50E40` (the struct base), the code
interprets the struct as a hash table. The struct doesn't contain valid
hash table entries, so the probe loop walks through garbage, eventually
reaching unmapped memory.

## Fix Attempts

### Attempt 1: Set metadata fields to struct base
Set 32 fields (`0x801E51200`–`0x801E51300`) to `0x801E50E40`.
**Result:** Previous crash at `0x8014327CF` cleared ✓, but new crash at
`0x8008067AC` (hash table probe loop). **Reverted.**

### Attempt 2: (Not attempted) Set fields to 0 (NULL)
Would cause SIGSEGV at `[NULL + offset]` which is recovered, but the
recovery cascade still prevents il2cpp_init from returning.

## Root Cause (Systemic)

il2cpp_init reads **many** metadata fields (255 references found) that are:
1. Zeroed by the once-init callback
2. Set by the hash lookup at `0x8013EEFE7` (AFTER il2cpp_init)

On real PS5:
- The metadata list is empty → callback returns 0 → call [0] → kernel handles
- il2cpp_init returns normally → hash lookup runs → metadata fields set
- Subsequent reads work

On SharpEmu:
- Metadata list is populated (premature registration) → callback returns non-zero
- Callback reads NULL metadata → crash
- EXP-048 stub-ret allows progress → other NULL metadata reads → crash
- il2cpp_init never returns → hash lookup never runs → metadata stays NULL

### The fundamental issue
The premature registration (EXP-045/046) causes the metadata list to be
populated before il2cpp_init. This makes the callback find entries and
return non-zero, triggering code that reads uninitialized metadata.

**Without fixing the premature registration, any approach (stub-ret, NOP,
flag hack) will hit more NULL metadata reads.**

## Next Step (EXP-050)

### Option A: Fix premature registration (root cause)
Find what populates the metadata list at `[0x801EA4E80]` before il2cpp_init.
The registration functions run via the init function's first-time path.
If they can be deferred until AFTER il2cpp_init, the metadata list stays
empty, the callback returns 0, and il2cpp_init returns normally.

### Option B: Make il2cpp_init return despite crashes
The SIGSEGV recovery allows execution to continue. If the cascade can be
contained (not reach the fatal loop at 0x80080684D), il2cpp_init might
eventually return. Then the hash lookup would set the metadata fields.

### Option C: Pre-populate the hash table
Manually fill the hash table entries from the metadata table at `0x1CC0080`
before il2cpp_init. This would allow the hash lookup to succeed early,
setting the metadata fields before they're read.
