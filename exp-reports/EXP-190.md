## C) Missing Features Causing Current Failures

### REVISED: DT_SCE_INIT_ARRAY Hypothesis is WRONG

**Prosper's self_dump tool labels:**
- `0x61000017` = `DT_SCE_EXPORT_LIB_ATTR` (NOT DT_SCE_INIT_ARRAY!)
- `0x61000019` = `DT_SCE_IMPORT_LIB_ATTR` (NOT DT_SCE_INIT_ARRAYSZ!)

**These are library attribute tags, NOT init_array tags!**

**Prosper also only parses standard DT_INIT_ARRAY (0x19) and DT_INIT_ARRAYSZ (0x1B)** — the same as SharpEmu. Yet Prosper runs IL2CPP games successfully.

### REAL Issue: DT_INIT Function Pointer Tables Populated by RELA

The PRX's DT_INIT function (`0x804CD5010`) iterates TWO function pointer tables:
- **Table 1:** 182,440 R_X86_64_RELATIVE entries populate this table
- **Table 2:** 321 R_X86_64_RELATIVE entries populate this table

These RELA relocations fill the tables with function pointers. SharpEmu DOES process R_X86_64_RELATIVE relocations, so these tables SHOULD be populated.

**The critical question is whether SharpEmu correctly applies these 182,440+ relocations to the PRX's writable data segment.** If the relocations are applied correctly, DT_INIT will iterate the populated tables and call the registered functions (including `s_Il2CppCodegenRegistration`).

### What needs verification:
1. Are the RELA relocations targeting the correct memory addresses after PRX loading?
2. Is the PRX's writable segment mapped at the correct base address?
3. Does the DT_INIT function successfully iterate the tables?
4. Does `il2cpp_codegen_register` get called during DT_INIT execution?

## Summary

### EXP-187/188/189 Hypothesis: REVISED

The hypothesis that SharpEmu is missing DT_SCE_INIT_ARRAY (0x61000017) parsing was **WRONG**. Tags 0x61000017 and 0x61000019 are `DT_SCE_EXPORT_LIB_ATTR` and `DT_SCE_IMPORT_LIB_ATTR` — library attribute tags, NOT init_array tags. Prosper confirms this labeling and also does not parse these as init_array.

### REAL Root Cause (Revised)

The PRX's DT_INIT function iterates function pointer tables that are populated by **182,440 R_X86_64_RELATIVE relocations**. SharpEmu has the code to process these relocations, but we need to verify:

1. Whether the relocations are actually applied to the correct memory addresses
2. Whether the DT_INIT function successfully calls the registered functions
3. Whether `s_Il2CppCodegenRegistration` (registered via these relocations) is called
4. Whether `il2cpp_codegen_register` executes and sets `g_CodeRegistration`/`g_MetadataRegistration`

### Next Step

Add runtime logging to verify:
1. RELA relocations are applied to the PRX's writable segment
2. DT_INIT function iterates the populated tables
3. Function pointers are valid (non-NULL, in code segment)
4. `il2cpp_codegen_register` is called during DT_INIT execution
