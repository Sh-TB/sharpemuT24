# EXP-055 — Find IL2CPP Registration Entry Point (Tier A + E)

## Date: 2026-07-31
## Status: COMPLETE — MetadataRegistration found; PRX DT_INIT is invalid (ELF header); upstream has same issue

---

## Executive Summary

Executed Tier A (tasks 1-10) and Tier E (tasks 43-44) of the EXP-055 master plan.

**Key breakthroughs:**

1. **Il2CppMetadataRegistration struct FOUND at `0x80885C580`** (PRX data segment 2).
   Contains (count, pointer) pairs for all metadata arrays. `types[]` pointer is
   at offset `+0x80` → `0x80893E950` (13,082 entries).

2. **PRX DT_INIT is INVALID**: `dt_init = 0x804CD5010 = imageBase + 0x10`, which
   points into the ELF header (bytes `18 fe 3e 00 01 00 00 00...`), NOT executable
   code. SharpEmu calls this garbage via `DispatchModuleInitializer`, which either
   crashes or gets recovered by the exception handler.

3. **PRX has NO init_array or fini_array** — DT_INIT_ARRAY and DT_FINI_ARRAY are
   both missing from the PRX's dynamic section.

4. **Upstream SharpEmu has the SAME issue** — the upstream repo
   (`sharpemu/sharpemu`) contains the comment: "On current PS5 dumps DT_INIT
   commonly resolves to imageBase+0x10, which is inside the mapped ELF header
   rather than a callable guest routine. Startup must remain guest-driven until
   the PS5 init/module ABI is identified precisely."

5. **CodeRegistration has 7,780 RIP-relative refs** but ALL load it into `rsi`
   (arg1), not `rdi` (arg0). The registration function takes CodeReg as its
   SECOND argument. The first argument (`rdi`) is unknown.

6. **MetadataRegistration has 0 RIP-relative refs** — it's not accessed via LEA.
   No relocation points to it either. It must be accessed via a register-loaded
   pointer, possibly from a global variable that's populated at runtime.

## Task 1-2: CodeRegistration References

### Findings

- **7,780 RIP-relative refs** to `0x8086E9000` (CodeRegistration) in PRX code
- First 10 refs all use `lea rsi, [rip + ...]` — loading CodeReg into `rsi` (arg1)
- None load into `rdi` (arg0)
- The first ref (`0x804F65288`) is in a small error-handling function (calls
  allocator + thrower, ends with `ud2`) — NOT the registration function

### Conclusion

CodeRegistration is used extensively throughout the PRX but always as the second
argument to various functions. The registration function (if it exists) takes
CodeReg as arg1, with something else as arg0.

## Task 5-6: Il2CppMetadataRegistration Found

### Struct at `0x80885C580` (PRX data segment 2)

Discovered via relocation search: a RELATIVE reloc at `0x80885C600` writes the
address of the `types[]` array (`0x80893E950`). Expanding the search revealed
a structured layout at `0x80885C580`:

```
Il2CppMetadataRegistration @ 0x80885C580:
  +0x00: 0x0                    (reserved/version)
  +0x08: 0x0
  +0x10: 0x0
  +0x18: 0x2FCE (12,270)        count for +0x20 array (typeDefinitions?)
  +0x20: -> 0x80874AB10 (data1) typeDefinitions array
  +0x28: 0x1F53 (8,019)         count for +0x30 array
  +0x30: -> 0x808781EB0 (data1)
  +0x38: 0x1969D (103,581)      count for +0x40 array
  +0x40: -> 0x808422E60 (rodata)
  +0x48: 0x9D76 (40,310)        count for +0x50 array (metadataUsages!)
  +0x50: -> 0x8088944F0 (data1) metadataUsages array (40,310 entries)
  +0x58: 0x1DE72 (122,482)      count for +0x60 array
  +0x60: -> 0x8082BC100 (rodata)
  +0x68: 0x32B2 (12,981)        count for +0x70 array
  +0x70: -> 0x8089253C0 (data2)
  +0x78: 0x32B2 (12,981)        count for +0x80 array (types!)
  +0x80: -> 0x80893E950 (data2) types[] array (13,082 entries)
  +0x88: 0x0
  +0x90: 0x0
  +0x98: -> 0x8089E9D90 (data2) field offsets?
  +0xA8: -> 0x8089E9D90 (data2)
  ... (more data2 pointers)
```

### Field layout match

The struct has 7 (count, pointer) pairs, matching Unity's
`Il2CppMetadataRegistration`:
- `typeDefinitions` (12,270 entries)
- `genericClasses` (8,019 entries)
- `genericInstances` (103,581 entries)
- `metadataUsages` (40,310 entries — matches the 40,310-entry array found earlier)
- `genericContainers` (122,482 entries)
- `nestedTypes` (12,981 entries)
- `types` (12,981 entries — matches `types[]` at `0x80893E950`)

### Access pattern

MetadataRegistration has **0 RIP-relative refs** in the PRX code. No relocation
points to it. This means:
- It's NOT accessed via `lea reg, [rip + ...]`
- It's NOT stored in any static global variable (no reloc with addend = 0x80885C580)

The only way to access it is via a register-loaded pointer, possibly:
1. A global variable populated at runtime (BSS, written by some init code)
2. A field in CodeRegistration (but CodeReg's fields don't point to MetadataReg)
3. Computed from another base address

## Task 3-4: PRX Constructor Audit

### Findings

- **DT_INIT_ARRAY**: NOT FOUND in PRX dynamic section
- **DT_FINI_ARRAY**: NOT FOUND in PRX dynamic section
- **DT_INIT** (`0x61000019` or standard `0x0C`): resolves to `imageBase + 0x10`
  = `0x804CD5010`, which is inside the ELF header (NOT executable code)

### PRX DT_INIT is invalid

```
PRX dt_init = 0x804CD5010 = PRX_BASE + 0x10
File offset 0x10 contains ELF header bytes: 18 fe 3e 00 01 00 00 00 ...
```

SharpEmu calls `DispatchModuleInitializer(0x804CD5010)`, which attempts to
execute ELF header bytes as code. This either:
1. Crashes immediately (SIGSEGV/SIGILL) and gets recovered by exception handler
2. Executes a few garbage instructions before hitting an INT3 or invalid opcode

### EXP-044's "11 fini_array entries" revisited

EXP-044 reported "PRX fini_array has 11 entries (RELATIVE relocations)". This
was WRONG — the PRX has NO `DT_FINI_ARRAY` dynamic entry. The 11 entries
EXP-044 found were likely from a different segment or a misidentified structure.

## Task 7-10: Registration Function Search

### Findings

- **0 eboot relocs** with addend matching CodeRegistration or MetadataRegistration
- **1,206 non-RELATIVE symbol relocs** in eboot (type 1 = R_X86_64_64, type 6 =
  R_X86_64_GLOB_DAT) — these are import stubs, not registration calls
- **No PRX export/NID** matching `il2cpp_codegen_register` or similar
- **No 3-argument call pattern** found (CodeReg, MetadataReg, codeGenModules)

### Registration function not found via static analysis

The registration function that takes (CodeReg, MetadataReg) as arguments was
NOT found via static analysis. Possible reasons:
1. It's called via an indirect call (`call [reg]`) that can't be resolved statically
2. It's inside `il2cpp_init` itself, but `il2cpp_init` crashes before reaching it
3. It's in a different module (libc.prx, PS5Util.prx) that we haven't checked
4. It doesn't exist — Unity's IL2CPP runtime uses a different initialization pattern

## Task 43-44: Upstream SharpEmu Check

### Upstream repo: `sharpemu/sharpemu`

Cloned and searched. Key findings:

1. **Same architecture**: Upstream has the same `RunPreloadedModuleInitializers`
   and `CollectInitializerFunctions` code as the T24 fork.

2. **Same DT_INIT issue**: The upstream `SharpEmuRuntime.cs` (line 442-444)
   contains this comment:
   ```
   // On current PS5 dumps DT_INIT commonly resolves to imageBase+0x10, which is inside
   // the mapped ELF header rather than a callable guest routine. Startup must remain
   // guest-driven until the PS5 init/module ABI is identified precisely.
   ```
   This confirms the upstream developers are aware of the issue but haven't
   solved it.

3. **No IL2CPP registration code**: Searched for `il2cpp_init`,
   `Il2CppCodeRegistration`, `Il2CppMetadataRegistration`, `codegen_register`,
   `metadata_register`, `g_MetadataRegistration`, `g_CodeRegistration` —
   **0 matches** in the upstream source.

4. **No issue tracker solutions**: The upstream repo has recent commits (Jul 2026)
   but none mention IL2CPP metadata registration or `il2cpp_init` crashes.

### Conclusion

The upstream SharpEmu does NOT have a fix for this issue. The IL2CPP metadata
registration problem is unsolved in both the T24 fork and the upstream repo.

### Confirmed facts

| Item | Value |
|------|-------|
| Il2CppCodeRegistration | `0x8086E9000` (PRX data1) |
| Il2CppMetadataRegistration | `0x80885C580` (PRX data2) |
| types[] array | `0x80893E950` (13,082 entries, in MetadataReg +0x80) |
| methodPointers[] | `0x808791958` (103,816 entries, in CodeReg +0x28) |
| metadataUsages[] | `0x8088944F0` (40,310 entries, in MetadataReg +0x50) |
| CodeReg RIP-relative refs | 7,780 (all load into `rsi`/arg1) |
| MetadataReg RIP-relative refs | 0 |
| MetadataReg reloc refs | 0 |
| PRX DT_INIT | `0x804CD5010` = imageBase+0x10 (ELF header, INVALID) |
| PRX DT_INIT_ARRAY | NOT FOUND |
| PRX DT_FINI_ARRAY | NOT FOUND |
| Upstream fix | NONE (same issue, acknowledged in comment) |

### Disproved hypotheses

- ❌ "EXP-044 found 11 PRX fini_array entries" — PRX has NO fini_array
- ❌ "The registration function takes CodeReg as arg0" — all refs load into arg1
- ❌ "MetadataRegistration is accessed via RIP-relative LEA" — 0 refs found
- ❌ "Upstream SharpEmu has a fix" — same issue, acknowledged but unsolved

### Confirmed hypotheses

- ✅ "Il2CppMetadataRegistration exists in PRX" — found at `0x80885C580`
- ✅ "PRX DT_INIT is invalid (ELF header)" — confirmed, matches upstream comment
- ✅ "The missing registration is the root cause" — PRX has no valid init mechanism

### Remaining hypotheses

1. **The registration function is inside `il2cpp_init`** — `il2cpp_init` crashes
   before reaching the registration code because the hash table is empty (circular
   dependency).

2. **The registration function is called via an indirect call** — resolved at
   runtime from a global pointer that's populated by some early init code.

3. **The PS5 loader has a special mechanism** for IL2CPP PRX initialization that
   SharpEmu doesn't implement — possibly a `module_start` callback or a
   SCE-specific init array type.

4. **The registration happens during `sceKernelLoadStartModule`** — the PS5
   loader might run the registration synchronously during module load, before
   returning the module handle. SharpEmu's loader skips this.

## Next Step (EXP-056)

### Implement the manual registration call

Since the registration function can't be found via static analysis, implement
a runtime approach:

1. **After PRX load, before `il2cpp_init`**: Call a C# function that:
   a. Loads CodeReg address (`0x8086E9000`) into `rsi`
   b. Loads MetadataReg address (`0x80885C580`) into `rdi` (or vice versa)
   c. Calls the wrapper `0x800805AE0` in a loop for each type name

2. **Alternative**: Hook `il2cpp_init` entry and manually populate the hash
   table by iterating the `types[]` array and calling the wrapper for each
   type's name string.

3. **Alternative**: Find the registration function by tracing `il2cpp_init`'s
   early code path — it likely calls the registration before the callback.
   Set INT3 at `il2cpp_init` entry and single-step through the first 100
   instructions to find the registration call.

### Target: BOOT_STAGE_5

Once the hash table is populated with real type metadata, the init function's
lookups will return non-NULL, metadata globals will be set, and `il2cpp_init`
can progress past the callback crash.
