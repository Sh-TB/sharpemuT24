# EXP-046 — Metadata Lookup Path Investigation

## Date: 2026-07-30
## Status: COMPLETE — Crash is from call #8, not call #7

---

## Executive Summary

**Key correction:** Call #7 (`call [rax]` at `0x804F04C5C`) calls
`0x804D9C620` which is a **function epilogue** (pop registers + ret).
It returns immediately. The crash is from **call #8** (`0x804F23320`)
which runs AFTER call #7 and calls the callback `0x80134FA00`.

The metadata lookup at `0x80134FA69` returns `rax = 0x801EC0C78`.
`[rax] = 0x80135DDD0` (function pointer to crash function).
`call [rax]` calls `0x80135DDD0` which reads `0x801E51240 = 0` → crash.

On a real PS5, the metadata lookup should return 0 (no match found)
because the metadata list should be empty at this point. The registration
functions haven't populated it yet on real PS5.

## Task 3 — SIGSEGV Recovery Analysis

### Call #7 target
```
[EXP041-CALL7] rax=0x808958220 [rax]=0x804D9C620 rdi=0x2
```

`0x804D9C620` is a **function epilogue** (pop rbx; pop r14; pop rbp; ret).
Call #7 returns immediately. The crash is NOT from call #7.

### Crash path
```
Call #7 → 0x804D9C620 (epilogue, returns immediately)
Call #8 → 0x804F23320 (metadata registration)
  → calls callback 0x80134FA00
    → call [0x801EA49D8] = 0x800C66B40 (metadata lookup)
      → returns 0x801EC0C78 (non-zero, search found match)
    → call [rax] = call [0x801EC0C78] = call 0x80135DDD0
      → reads [0x801E51240] = 0 → CRASH at 0x80135DE83
```

## Task 4 — Callback Object Selection

### Why SharpEmu selects 0x80135DDD0
The metadata lookup at `0x800C66B40` searches the metadata list at
`[0x801EA4E80]`. The list is populated because registration functions
have already run (via the init function's first-time path).

The lookup finds a matching entry and returns `[entry+0x30]` which is
a pointer to `0x80135DDD0`. The `call [rax]` then calls this function.

On a real PS5, the list should be empty (only original node, flag=1).
The lookup would see flag=1 and return 0 (early exit). `call [0]` would
be handled by the kernel (returns to caller with rax=0).

---

## Root Cause

The metadata list at `[0x801EA4E80]` is populated prematurely on
SharpEmu because registration functions run during the init function's
first-time path (via the iterator at `0x800B8D530`). These registration
functions add entries to the metadata list with flag=0.

On a real PS5, the registration functions either:
1. Run LATER (after il2cpp_init)
2. Don't add entries to THIS specific list
3. Add entries with flag=1 (initialized)

The metadata lookup finds these entries and returns non-zero, causing
the callback to call `0x80135DDD0` which reads `0x801E51240 = 0` → crash.

## Next Step (EXP-047)

1. **Trace call #8 (`0x804F23320`):** Add INT3 at call #8 to verify it
   runs and calls `0x80134FA00`.

2. **Prevent metadata list population:** Find what populates the metadata
   list at `[0x801EA4E80]` before call #8 runs. The registration functions
   add entries via the iterator. If the iterator can be deferred, the list
   stays empty and the lookup returns 0.

3. **Set metadata flag to 1:** Before call #8, set `[rdx+0x19] = 1` for
   all entries in the metadata list. This forces the lookup to return 0
   (early exit), matching real PS5 behavior.

4. **Handle NULL call correctly:** If the lookup returns 0, `call [0]`
   causes SIGSEGV. The recovery should return rax=0 and continue. But
   the code after `call [rax]` calls `0x801352760` which also reads
   `0x801E51240 = 0` → crash. Need to handle this differently.
