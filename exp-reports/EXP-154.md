## Task 2: Trace Type Initialization

### Flag Ownership

| Flag | Owner | Current Value | Why |
|------|-------|---------------|-----|
| 0x808D67B98 | il2cpp_runtime_class_init | 0 (BSS) | Function never runs — GOT has garbage |
| 0x808D67BB8 | il2cpp_runtime_class_init | 0 (BSS) | Same — chicken-and-egg guard |
| 0x808B55690 | Unknown (0 writers) | 0 (BSS) | Does NOT block (guard checks == 2) |

### Structure Analysis

The flags are part of a structure at 0x808D67B90:
- **168 LEA instructions** load this structure base address into registers
- The structure has fields at offsets +0x8, +0x10, +0x18, +0x20, +0x28
- Field at +0x20 (0x808D67BB0) has 70 writers — it's a bitmap/counter, actively maintained
- Fields at +0x8 and +0x28 are the type initialized flags — NEVER set

### How the Flags Should Be Set

On real PS5/Unity IL2CPP:
1. Guest code calls `il2cpp_runtime_class_init(class_ptr)` through the GOT
2. `il2cpp_runtime_class_init` runs the type's .cctor (static constructor)
3. After .cctor completes, it sets the type's initialized flag (at +0x8 or +0x28)
4. Subsequent calls to the gate function see the flag is non-zero and allow method execution

On SharpEmu:
1. Guest code calls `il2cpp_runtime_class_init` through the GOT
2. GOT contains garbage (0x7FD670094000 instead of 0x804ED9590)
3. CPU jumps to garbage address — either crashes or does nothing useful
4. Type initialized flags are NEVER set
5. Gate function always returns early — all methods are skipped

## Task 4: Validate EXP-138 Fix

### Source Verification

The EXP-138 fix is verified in source code:

**File:** `DirectExecutionBackend.cs`
**Location:** Lines 4891-5106

The fix works as follows:
1. **Line 4895:** Allocate a native buffer (`raxCaptureSlot`) to capture 64-bit RAX
2. **Line 4998-5003:** Emit native code to save host RAX to `raxCaptureSlot` before returning
3. **Line 5063:** Run the guest function via `RunGuestEntryStub`
4. **Line 5068:** Read the captured RAX: `var capturedRax = *raxCaptureSlot;`
5. **Line 5069:** Write to context: `context[CpuRegister.Rax] = capturedRax;`

### Call Chain Verification

```
TryCallGuestFunction (line 3368)
  → ExecuteGuestThreadEntry (line 3490)
    → RunGuestEntryStub (line 5063)
    → capturedRax = *raxCaptureSlot (line 5068)  ← EXP-138 FIX
    → context[CpuRegister.Rax] = capturedRax (line 5069)  ← EXP-138 FIX
  → returnValue = context[CpuRegister.Rax] (line 3503)  ← reads correct value
```
