# EXP-192 — Trace DT_INIT Callback Abort Root Cause

**Date:** 2026-08-10
**Status:** ROOT CAUSE FOUND — Missing C++ exception handling HLE
**Predecessor:** EXP-191 (DT_INIT calls callbacks, one hits abort)

---

## 1. Callback Purpose

The DT_INIT callback at `0x804FC2470` is a C++ static initializer / IL2CPP registration function. It:
1. Clears a flag: `mov byte [rip+0x03DA6A85], 0`
2. Calls `0x804FC1D80` (initialization function)
3. Performs SIMD operations (vmovdqu/vmovupd)

Function `0x804FC1D80` calls `0x804FC24E0` (hash/comparison function) and then performs various initialization steps including calls to `0x805002AE0` and `0x804FC0750`.

## 2. Abort Condition

**The abort is caused by `std::terminate()` triggered by an unhandled C++ exception.**

**Evidence:**
- Crash at `0x8040365AF` in libc.prx
- Code at RIP: `0F 0B 48 89 C7 E8 B7 CF FD FF 0F 0B` (UD2; mov rdi,rax; call handler; UD2)
- RIP symbol: `Zb+hMspRR-o#D#A+0x2F` → NID `Zb+hMspRR-o` = **`_ZSt13get_terminatev`** (std::get_terminate())
- This function is called by `std::terminate()` when an exception is not caught

**Call chain:**
```
DT_INIT → 0x804FC2470 (callback) → 0x804FC1D80 → ... 
  → C++ exception thrown
  → No catch handler (SharpEmu doesn't implement __cxa_throw/__cxa_begin_catch)
  → std::terminate()
  → std::get_terminate() at 0x8040365AF
  → UD2 (abort)
```

## 4. Root Cause

**Classification: C) Missing HLE implementation**

SharpEmu does NOT implement C++ exception handling functions:
- `__cxa_allocate_exception` (NID: `cfAXurvfl5o`)
- `__cxa_throw` (NID: `vkuuLfhnSZI`)
- `__cxa_begin_catch` (NID: `3cUUypQzMiI`)
- `__cxa_end_catch` (NID: `lX+4FNUklF0`)

When the DT_INIT callback throws a C++ exception (likely during IL2CPP metadata loading or type initialization), SharpEmu's import dispatcher returns `ORBIS_GEN2_ERROR_NOT_FOUND` for `__cxa_throw`. This causes the exception to be unhandled, triggering `std::terminate()` → `std::get_terminate()` → abort().

## 5. Minimal Fix Location

**File:** `src/SharpEmu.Libs/CxxAbiExports.cs` or `src/SharpEmu.Libs/Kernel/KernelMemoryCompatExports.cs`

**Required implementations:**

1. `__cxa_allocate_exception` — Allocate exception object on heap
2. `__cxa_throw` — Set exception state, don't actually throw (or use host exception mechanism)
3. `__cxa_begin_catch` — Return exception object, increment catch count
4. `__cxa_end_catch` — Decrement catch count, free if count == 0

**Approach:**
- Allocate a fake exception object (small heap allocation)
- `__cxa_throw`: Store the exception pointer in a thread-local global, return
- `__cxa_begin_catch`: Return the stored exception pointer
- `__cxa_end_catch`: Clear the stored pointer
- This allows the exception to be "caught" without actually unwinding the stack

**Alternative approach (simpler):**
- `__cxa_throw`: Return immediately (suppress the exception)
- `__cxa_begin_catch`: Return NULL (no exception)
- `__cxa_end_catch`: Return (no-op)
- This silently swallows all exceptions — may cause issues later but prevents abort

## 6. Regression Test

1. Implement `__cxa_throw` as a no-op (return immediately)
2. Implement `__cxa_begin_catch` returning NULL
3. Implement `__cxa_end_catch` as no-op
4. Implement `__cxa_allocate_exception` returning a small heap allocation
5. Run Yatzi with `SHARPEMU_GUEST_ARGS="dummy_arg"`
6. Verify: DT_INIT callback no longer hits abort()
7. Verify: il2cpp_init reaches `il2cpp_codegen_register`
8. Verify: `[0x801E51240]` becomes non-NULL
