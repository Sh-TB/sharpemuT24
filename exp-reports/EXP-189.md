### 5. Sony init_array Format

**DT_SCE_INIT_ARRAYSZ entries:**
- One entry per dependency (library)
- Format: `(dependency_index << 48) | size`
- All entries have size = 0x09 (9 bytes per dependency)

**DT_SCE_INIT_ARRAY entry:**
- One entry for the module itself
- Format: `(module_index << 48) | count_or_offset`
- EBOOT: module_index = 0x0026 (38), count = 1
- PRX: module_index = 0x000A (10), count = 1

**Both EBOOT and PRX have 1 constructor function each** that should be called during module load.

### 6. External References

- **Katy's IL2CPP blog:** Confirms that `il2cpp_init` calls `ExecuteInitializations()` which iterates a function table populated by C++ constructors
- **shadPS4:** Has `init_array_virtual_addr` and `init_array_size` fields but no evidence of handling Sony-specific tags (0x61000017)
- **Il2CppInspector:** Uses `ImageScan` to find CodeRegistration/MetadataRegistration by scanning for pointer chains, not by parsing init_array
- **rtdump-il2cpp-ps4:** Uses `sceKernelDlsym` to resolve IL2CPP API functions, doesn't handle init_array directly
- **PS4 dev wiki:** No specific documentation found for DT_SCE_INIT_ARRAY format

No existing implementation found that handles Sony-specific init_array tags. The format appears to be PS4/PS5-specific and not documented publicly.

**The missing Sony initialization IS proven to block the runtime.**

## Root Cause

**SharpEmu does not parse Sony-specific `DT_SCE_INIT_ARRAY` (0x61000017) and `DT_SCE_INIT_ARRAYSZ` (0x61000019) dynamic tags.** Both EBOOT and PRX use these tags instead of standard `DT_INIT_ARRAY` (0x19) for their constructor function arrays. Without parsing these tags, SharpEmu never executes the PRX's constructor functions, which means:

1. `s_Il2CppCodegenRegistration` is never registered
2. `il2cpp_codegen_register` is never called
3. `g_CodeRegistration` and `g_MetadataRegistration` are never set
4. The IL2CPP runtime is not fully initialized
5. `[0x801E51240]` (Il2CppClass*) stays NULL
6. Crash at `[NULL+0x98]` (Il2CppClass.methods field)
