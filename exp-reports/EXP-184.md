## 2. Missing Function/API/Data Identified

### What [0x801E51240] represents:

Based on the crash analysis:
- The crash function `0x80135DDD0` reads `[0x801E51240]` and accesses `[ptr+0x98]`
- Stack trace contains Unity IL2CPP class names: `FXExpressionValuesProxy`, `VisualEffectAssetProxy`, `Unity.Collections`
- 40 readers across eboot, all accessing it as a pointer to a structure

**[0x801E51240] is most likely the IL2CPP metadata registration pointer or the IL2CPP domain pointer.** This is the global that bridges EBOOT's Unity player code to the IL2CPP runtime in the PRX.

### What's missing:

**il2cpp_init on a real PS5 does more than just return 0.** The real `il2cpp_init` at `0x804ED85D0` (in the PRX) calls:
1. `setlocale(0x3F, ...)` — locale setup (works, returns)
2. `0x804F04BA0` — main IL2CPP initialization (returns 0)

But `0x804F04BA0` makes 508 calls internally, and NONE of them call back into EBOOT code. The PRX initializes its own internal state but does NOT set EBOOT's `[0x801E51240]`.

**The missing piece:** On a real PS5, the IL2CPP runtime initialization should trigger a callback or registration mechanism that tells EBOOT code to set `[0x801E51240]`. This could be:
1. A function pointer callback from PRX to EBOOT
2. A shared global that both PRX and EBOOT can access
3. A code generation registration (`il2cpp_codegen_register`) that EBOOT calls after `il2cpp_init`

### il2cpp_init's first callee = setlocale:

```
il2cpp_init (0x804ED85D0):
  call setlocale(0x3F, data_ptr)  → NID: PtsB1Q9wsFA (PLT index 0x5C)
  call 0x804F04BA0 (main init)
  return 0
```

`setlocale` is a standard libc function. SharpEmu has it implemented. This call works correctly.

### il2cpp_init's second callee = 0x804F04BA0:

This function (508 calls) performs the actual IL2CPP runtime initialization. It does NOT call back into EBOOT. It initializes PRX-internal state only.

## 3. Evidence Why [0x801E51240] Remains NULL

### Complete evidence chain:

1. **Only 2 code writers exist** (EXP-183):
   - `0x8007FD8F9`: `mov qword [0x801E51240], 0x0` (clear — executes early)
   - `0x8013EF019`: `mov [0x801E51240], rax` (init — on ERROR path, never reached)

2. **No relocations** target this address (no GLOB_DAT, no JUMP_SLOT)

3. **PRX cannot write** to this address (different address space)

4. **Consumer success path** (EXP-182):
   - Takes `je` at +0x19B1 (il2cpp_init returned 0)
   - Makes 160 CALLs — NONE write to [0x801E51240]
   - Has 14 RET instructions — exits without reaching +0x3969

5. **Parent function** after consumer returns:
   - Checks stack canary
   - Returns immediately
   - Does NOT write to [0x801E51240]

6. **il2cpp_init** (0x804ED85D0):
   - Calls `setlocale` (works)
   - Calls `0x804F04BA0` (works, returns 0)
   - Does NOT call back into EBOOT
   - Does NOT set any EBOOT globals

7. **Earliest reader** of [0x801E51240]:
   - At `0x800468397` (function `0x8004682D0`)
   - This function has ZERO callers — dead code
   - First ACTUAL reader at runtime: crash function `0x80135DDD0`

### Conclusion:

**[0x801E51240] is NULL because the init writer at `+0x3969` is on the ERROR path, and il2cpp_init returns 0 (success) which takes the SUCCESS path.** The success path does NOT initialize `[0x801E51240]`, and no other code (parent, il2cpp_init, or PRX) initializes it either.

The fundamental issue is that **SharpEmu's IL2CPP runtime initialization is incomplete**. On a real PS5, the IL2CPP runtime initialization (inside `0x804F04BA0` or a function it calls) should register metadata with EBOOT code, which would set `[0x801E51240]`. This registration mechanism is missing.

## 5. Recommended Minimal Fix (After Proof)

### Option A: Initialize [0x801E51240] via HLE after il2cpp_init returns

Since the consumer's success path doesn't set `[0x801E51240]`, and il2cpp_init's native code doesn't set it either, SharpEmu should set it via HLE:

1. After il2cpp_init returns 0, set `[0x801E51240]` to a valid IL2CPP metadata pointer
2. The pointer should point to a fake metadata structure with the expected fields at offset 0x98

**Risk:** The fake structure may not have all required fields, causing crashes later.

### Option B: Implement il2cpp_codegen_register HLE

The real IL2CPP runtime calls `il2cpp_codegen_register` to register type metadata. This function may be what sets `[0x801E51240]` on a real PS5. Check if this NID exists in the PRX's imports and implement it.

### Option C: Check for a missing GLOB_DAT or indirect initialization

There may be a function pointer or callback that should be called during IL2CPP init to set `[0x801E51240]`. This would be in the PRX's initialization code and would call back into EBOOT.

**Recommended next step:** Before implementing any fix, check if `il2cpp_codegen_register` or similar metadata registration function exists in the PRX's import table and whether SharpEmu handles it.
