## Key Findings

### 1. Dependency Object Identity

The dependency at `[rbx+0x108]` is **NOT a separate async object** — it's a **chain dependency pointer** to the PREVIOUS worker's task descriptor.

**Evidence:**
- Worker descriptors are allocated sequentially, 0x140 bytes apart:
  - Worker 1: `0x6006D0FF0`
  - Worker 2: `0x6006D1130` (= Worker 1 + 0x140)
  - Worker 3: `0x6006D1270` (= Worker 2 + 0x140)
- Worker 2's `[rbx+0x108]` = `0x6006D1101` (tagged) → `0x6006D1100` (untagged)
- `0x6006D1100` = Worker 1's base + 0x110 = `0x6006D0FF0 + 0x110`
- **Worker 2 depends on Worker 1's field at +0x110**

This is a **worker chain dependency** — Worker N depends on Worker N-1.

### 2. Task Function Pointer Source

The task function pointer `[rbx+0xf8]` is set by **PRX code** (170 write sites in Il2cppUserAssemblies.prx), NOT by eboot code.

**Evidence:**
- 0 writes to `[reg+0xf8]` in eboot's worker code region (0x800A80000-0x800AC0000)
- 0 writes in SET function (0x800A9F9A0), CLEAR function (0x800A9F750), WORKER function (0x800AA0170), or ENTRY function (0x800BB06A0)
- 170 writes to `[reg+0xf8]` in the PRX (addresses like 0x804E5F571, 0x805252164, etc.)

**The eboot only READS [rbx+0xf8] — it never writes it.** The PRX's Unity runtime is responsible for dispatching tasks by writing the function pointer.

### 3. Why Completion Never Happens

The PRX's task dispatch code (170 sites) is **never reached** because:
1. Unity runtime initialization doesn't complete
2. The game never reaches VideoOut/GPU initialization (0 sceVideoOut calls)
3. A prerequisite subsystem (likely GPU/graphics) is not implemented in SharpEmu
4. Without GPU init, Unity can't proceed to task dispatch
5. Without task dispatch, [rbx+0xf8] stays NULL
6. Workers spin on NULL forever

### 4. The Full Root Cause Chain

```
SharpEmu doesn't implement GPU/graphics initialization (sceVideoOut, sceAgc)
↓
Unity runtime initialization can't complete (missing GPU subsystem)
↓
PRX task dispatch code never runs (170 write sites for [rbx+0xf8] never reached)
↓
[rbx+0xf8] stays NULL (task function pointer never set)
↓
Workers call NULL → TryRecoverNullExecuteFault → 1000+ recoveries
↓
Host stack corruption → SIGABRT
```

The dependency at `[rbx+0x108]` (chain pointer to previous worker) is a **secondary issue** — even without the dependency, workers can't run because `[rbx+0xf8]` is NULL (no task assigned).
