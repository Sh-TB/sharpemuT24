## 1. Goal

Validate the PRX initialization chain: RELA relocations → DT_INIT → function pointer calls → IL2CPP registration.

## 2. Instrumentation Added

1. **RELA relocation logging** (SelfLoader.cs): Counted and logged R_X86_64_RELATIVE relocations
2. **Targeted RELA table logging** (SelfLoader.cs): Logged writes to DT_INIT table addresses
3. **INT3 at DT_INIT call rax** (CpuDispatcher.cs + Exceptions.cs): Breakpoint at 0x804CD5072 to catch DT_INIT function pointer calls

## 3. Evidence Collected

### Test 1 — RELA Relocation Validation

**CONFIRMED: RELA relocations ARE applied correctly.**

- **400,000+ R_X86_64_RELATIVE relocations** processed and applied
- Target addresses span EBOOT (0x801C80010+) and PRX (0x804CD5000+) writable segments
- Values are valid: `imageBase + addend` formula produces correct absolute addresses

**DT_INIT table pointers populated by RELA:**
```
[0x808923E88] = 0x804CD50D0  (Table 1 end = Table 1 start → Table 1 EMPTY)
[0x8089247D8] = 0x804FC2470  (Table 2 first entry → function pointer)
```

**246,592 RELATIVE relocations** in PRX writable data segment (0x3A14000+) — these populate initialization data structures.

### Test 2 — DT_INIT Execution Validation

**CONFIRMED: DT_INIT IS calling function pointers from Table 2!**

INT3 at 0x804CD5072 (DT_INIT's `call rax` instruction) was HIT:
```
RIP: 0x804CD5073
RAX: 0x804FC2470  ← function pointer being called
RBX: 0x8089247D8  ← Table 2 start address
```

**DT_INIT successfully:**
1. Skipped Table 1 (start == end → empty)
2. Entered Table 2 loop
3. Read [0x8089247D8] = 0x804FC2470 (non-NULL, non-(-1))
4. Called 0x804FC2470

### Test 3 — Function Pointer Validation

**Function at 0x804FC2470 (PRX vaddr 0x2ED470):**
- Located in PRX read-only data segment (segment 1)
- Starts with `push rbp; mov rbp, rsp` — valid function prologue ✓
- SharpEmu maps entire image as RWX (executable) — call succeeds ✓

### Test 4 — IL2CPP Registration Proof

**PARTIALLY ANSWERED: DT_INIT calls function 0x804FC2470, but it hits abort()**

The function at 0x804FC2470 eventually calls a function in libc.prx (at 0x8040365AF) that executes **UD2 (0F 0B)** — an intentional abort/panic instruction.

**Crash details:**
```
RIP: 0x8040365AF (in libc.prx)
Code: 0F 0B 48 89 C7 E8 B7 CF FD FF 0F 0B CC CC CC CC
      UD2  mov rdi,rax  call handler  UD2  padding
```

**UD2 pattern analysis:**
- `0F 0B` = UD2 (undefined instruction — intentional abort)
- `48 89 C7` = mov rdi, rax (prepare error argument)
- `E8 B7 CF FD FF` = call 0x80403566B (error handler in libc)
- `0F 0B` = second UD2 (unreachable)
- `CC CC CC CC` = function padding

This is a standard `abort()` or `__builtin_unreachable()` pattern. The DT_INIT callback (0x804FC2470) encountered an error condition and called abort().

## 5. Confirmed Root Cause

**The DT_INIT callback at 0x804FC2470 calls abort() in libc.prx.**

The initialization chain works correctly up to the point where the DT_INIT callback executes. The callback (likely an IL2CPP registration function or C++ static initializer) encounters an error condition and calls abort().

The abort() is at 0x8040365AF in libc.prx — this is a standard `abort()` implementation with UD2 instructions.

**The root cause is NOT missing relocations or missing DT_INIT execution — it's a runtime error inside the DT_INIT callback that causes it to abort.**
