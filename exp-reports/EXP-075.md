## Question

**Who should signal semaphore handle 0x5C?**

## Answer

**The CLEAR function (`0x800A9F750`) should signal it.** The CLEAR function is an async callback that fires when the dependency at `[rbx+0x108]` is resolved. The dependency is never resolved because SharpEmu doesn't implement the completion event for the async Unity initialization step it represents.

### Semaphore Handle Map

| Handle | Operation | Who | Purpose |
|--------|-----------|-----|---------|
| 0x5C | WaitSema | Worker tid=26 | Worker's personal wait semaphore |
| 0x5E | WaitSema | Worker tid=27 | Worker's personal wait semaphore |
| 0x5F | SignalSema (via [rbx+0xB0]) | Worker code | Task completion signal |

### The Dependency Object at rbx-0x30

The tagged pointer `0x6006D1101` at `[rbx+0x108]` points to `0x6006D1100` (= `rbx - 0x30`). This is part of the same allocation — the task descriptor struct starts at `0x6006D1100` and `rbx` points 0x30 bytes into it.

The dependency object represents an **async Unity initialization step** that must complete before the task can be dispatched. When the dependency completes:
1. The CLEAR function (`0x800A9F750`) is called as an async callback
2. CLEAR writes `0x00` to `[rbx+0x108]` (clears the dependency pointer)
3. The gate at `0x800AA0207` passes (byte = 0)
4. The correct SignalSema call fires with the worker's handle (0x5C)
5. Workers wake up and execute the task

### Why the Dependency Never Completes

The async operation that the dependency represents **never completes** because SharpEmu doesn't implement the completion event. The dependency likely represents:
- A Unity subsystem initialization (e.g., graphics, audio, input)
- An asset loading operation
- A scene loading step

Without the completion event, the CLEAR callback never fires, the dependency pointer stays non-zero, and the correct semaphore (0x5C) is never signaled.

### Why the NOP Bypass Doesn't Work

The 11-byte NOP bypasses the gate check, allowing SignalSema to fire. But SignalSema uses `[rbx+0xB0]` (handle 0x5F) as the semaphore handle — this is the TASK's signal semaphore, not the WORKER's wait semaphore (0x5C). The correct handle (0x5C) is only loaded when the dependency is properly resolved through the CLEAR callback path.
