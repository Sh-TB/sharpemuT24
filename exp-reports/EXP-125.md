# EXP-125 — Find the Missing Signal Source for Main Thread Semaphore 0x81

**Date:** 2026-08-04
**Status:** COMPLETE — ROOT CAUSE IDENTIFIED
**Goal:** Find what should signal semaphore 0x81 (the main thread's job queue wait semaphore).

---

## Finding

**The producer code that should increment `[r14+0x90]` and signal semaphore 0x81 does NOT EXIST in either eboot.bin or Il2cppUserAssemblies.prx.** The counter at `[r14+0x90]` is only ever DECREMENTED by the consumer function at `0x804F6E978` (`lock xadd [r14+0x90], -1`). There is ZERO code in the entire game binary that INCREMENTS this counter.

**This means the producer must come from OUTSIDE the game binary** — from a runtime event, HLE callback, or OS-level primitive that SharpEmu does not fire. On real PS5, this would be Unity's main loop tick, driven by the display/vblank event system. When the vblank fires, Unity's main loop processes the frame, submits jobs to the job queue (incrementing `[r14+0x90]` and signaling semaphore 0x81), and the main thread wakes to dispatch them.

**SharpEmu does not fire the vblank/display event that would trigger this chain.** This is the missing HLE primitive.

## Dispatcher Function Analysis

The consumer function at `0x804F6E880` (called from `0x804F6E510`):

```asm
; Consumer loop (at 0x804F6E96D):
0x804F6E96D: mov eax, 0xFFFFFFFF        ; eax = -1
0x804F6E972: mov r15d, 0xFFFFFFFF
0x804F6E978: lock xadd [r14+0x90], eax  ; DECREMENT counter (consumer)
0x804F6E981: test eax, eax
0x804F6E983: jle 0x804F6E9DF            ; if counter <= 0, go to WaitSema
; ... process work item if counter > 0 ...

; WaitSema path (at 0x804F6E9DF):
0x804F6E9DF: mov rdi, [r14+0x88]        ; load semaphore handle (0x81)
0x804F6E9E6: call WaitSema              ; BLOCK HERE
0x804F6E9EB: lock xadd [rbx+0x10], r15d ; (return address — stall point)
```

The consumer:
1. Atomically decrements `[r14+0x90]` (the job count counter)
2. If the result is ≤ 0 (no jobs), loads the semaphore handle from `[r14+0x88]` and calls WaitSema
3. Blocks until the semaphore is signaled

## Root Cause Candidate

**The root cause is a missing HLE event/callback that should trigger Unity's main loop tick.**

The job queue producer is supposed to be Unity's main loop, which:
1. Receives a vblank/flip event from the display system
2. Processes the frame update
3. Submits jobs to the job queue (incrementing `[r14+0x90]`)
4. Signals semaphore 0x81 to wake the consumer

On real PS5, this chain is:
```
Display vblank → Unity main loop tick → job submission → increment [r14+0x90] → SignalSema(0x81) → consumer wakes
```

SharpEmu does not fire the vblank/flip event (because the game never reaches `sceVideoOutOpen`/`sceVideoOutSubmitFlip` — it blocks on WaitSema(0x81) before getting that far). This creates a chicken-and-egg problem:
- The main thread needs a vblank event to start processing
- The vblank event requires VideoOut to be initialized
- VideoOut initialization requires the main thread to progress past the job queue wait
- The main thread is blocked on the job queue wait because no vblank event fires

**The missing HLE primitive is the vblank/display event that triggers Unity's main loop tick.** Without it, the job queue counter is never incremented, semaphore 0x81 is never signaled, and the main thread blocks forever.

## Confirmed

1. **ZERO `lock xadd/inc/add [reg+0x90]` in eboot.bin** — CONFIRMED (static analysis, 0 sites)
2. **ZERO `lock xadd/inc/add [reg+0x90]` in Il2cppUserAssemblies.prx** (except the consumer decrement) — CONFIRMED (35 total [reg+0x90] accesses, 0 increments)
3. **ZERO SignalSema on handle 0x81** in both FAST_PATH=0 and FAST_PATH=1 — CONFIRMED (runtime logs)
4. **The producer does not exist in the game binary** — CONFIRMED (no increment code found anywhere)
5. **The consumer is the only code that touches [r14+0x90]** with a lock operation — CONFIRMED (1 site: 0x804F6E978, decrement)
6. **The enqueue function (0x804F6E880) has 1 caller** (0x804F6E6B8, inside function 0x804F6E510) — CONFIRMED
7. **Function 0x804F6E510 has 5 callers** (all in PRX, 0 in eboot) — CONFIRMED

## Rejected

1. **"The producer is in eboot.bin"** — REJECTED. Zero increment sites in eboot.bin.
2. **"The producer is in Il2cppUserAssemblies.prx"** — REJECTED. Zero increment sites in PRX (only the consumer decrement).
3. **"Semaphore 0x81 is signaled by a hidden code path"** — REJECTED. Zero SignalSema on 0x81 in both runtime logs.

## Unknown

1. **What specific HLE primitive should fire the vblank/display event?** Candidates:
   - `sceVideoOutAddVblankEvent` — registers a callback for vblank events
   - `sceVideoOutSubmitFlip` — triggers a flip which generates a vblank event
   - A timer/callback HLE primitive
   - A pthread condition variable that SharpEmu doesn't properly signal

2. **Is the chicken-and-egg problem (main thread needs vblank to progress, but vblank needs VideoOut which needs main thread to progress) the actual design, or is there a bootstrap mechanism?** On real PS5, Unity likely initializes VideoOut BEFORE entering the job queue loop. The game may not reach VideoOut init because it blocks on the job queue first.

3. **Would signaling semaphore 0x81 artificially (as a test) allow the main thread to progress to VideoOut init?** This would be a code change, which is not allowed in this EXP, but it's a candidate for a future test.

4. **Is there a Unity/Baselib initialization step that should submit the first job BEFORE the main loop starts?** The job queue might need a "bootstrap" job to kickstart the system.
