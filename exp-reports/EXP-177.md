## Root Cause

### Exact instruction where il2cpp_init stops returning:

**`0x804FC2C80` — PLT entry for NID `z+P+xCnWLBk`**

This is a PLT (Procedure Linkage Table) entry inside Il2cppUserAssemblies.prx that calls an unresolved import. The call chain is:

```
Consumer +0x19A7 (0x8013ED057): call [0x801ED6320] → il2cpp_init
  ↓
il2cpp_init (0x804ED85D0): call 0x804F04BA0
  ↓
0x804F04BA0: call 0x804F95AE0
  ↓
0x804F95AE0: call 0x804FC2C80 (PLT for z+P+xCnWLBk)
  ↓
0x804FC2C80: jmp [0x808924030] → HLE trampoline → DispatchImport
  ↓
DispatchImport: NID z+P+xCnWLBk has NO HLE handler
  ↓
Returns error → enters dispatch loop 0x800AA0170
  ↓
WaitSema(0x81) → DEADLOCK
```

### Why it blocks:

1. NID `z+P+xCnWLBk` is not implemented in SharpEmu's HLE
2. The import dispatch creates a trampoline that calls `DispatchImport`
3. `DispatchImport` has no handler for this NID
4. The return path enters the dispatch loop (0x800AA0170)
5. The dispatch loop blocks on WaitSema(0x81)
6. il2cpp_init never returns to the consumer
7. [0x801E51240] is never initialized
8. PlayerLoop is never registered
9. No VideoOut calls

### Identified: NID `z+P+xCnWLBk` is the blocking import

The exact blocking point is the PLT entry `0x804FC2C80` which calls NID `z+P+xCnWLBk`. This NID is not implemented in SharpEmu.

### Required investigation before any fix:

1. **Identify what `z+P+xCnWLBk` is** — search aerolib/PS5 SDK documentation for this NID
2. **Determine the expected behavior** — what should this function return/do?
3. **Check if it's a synchronization primitive** — the call happens inside il2cpp_init's initialization path, suggesting it might be a mutex/semaphore/thread creation function
4. **Check if it's a Baselib function** — Unity Baselib uses Sony SDK functions internally

Once `z+P+xCnWLBk` is identified:
1. Add an HLE handler in `DirectExecutionBackend.Imports.cs` (similar to `DispatchIl2CppApiLookupSymbol`)
