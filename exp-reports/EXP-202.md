## 4. THREAD HANDLE PROVENANCE

### Handle: `0x7FE764D84F10` (varies per run due to host heap ASLR)

| Step | Evidence |
|------|----------|
| **Allocation** | `Marshal.AllocHGlobal(ThreadObjectSize)` in `AllocateThreadHandle()` at `KernelPthreadState.cs:77` |
| **Registration** | `Threads[handle] = new ThreadIdentity(...)` at `KernelPthreadState.cs:81` |
| **Caller** | `EnsureCurrentThreadRegistered()` at `KernelPthreadState.cs:62`, called when `GuestThreadExecution.CurrentGuestThreadHandle == 0` |
| **Trigger** | `scePthreadSelf()` HLE at `KernelPthreadCompatExports.cs:99`: `var currentThreadHandle = KernelPthreadState.GetCurrentThreadHandle()` |
| **External registration** | `RegisterGuestThreadContext(currentThreadHandle, ctx)` at `KernelPthreadCompatExports.cs:100` → inserts into `_externalGuestThreads[handle]` |
| **Return to guest** | `ctx[CpuRegister.Rax] = currentThreadHandle` at `KernelPthreadCompatExports.cs:101` |
| **Guest stores handle** | Used at Import#182 as `rdi` to `scePthreadAttrGet` (line 10725 of log) |
| **Passed to RaiseException** | Import#83236: `rdi=0x7FE764D84F10` (target thread) |

### Semantic Identity

The handle is a **host-side heap pointer** returned by `Marshal.AllocHGlobal`. It is used as:
1. A `pthread_t` value (guest-visible thread identity)
2. A key in `KernelPthreadState.Threads` (pthread state registry)
3. A key in `_externalGuestThreads` (exception delivery registry)
4. An argument to `scePthreadAttrGet`, `scePthreadSetaffinity`, `scePthreadSetprio`, `pthread_equal`
5. The target of `sceKernelRaiseException`

This is **intentional** — SharpEmu uses host heap pointers as guest-visible pthread handles.

### Why Delivery Fails

`DeliverPendingGuestExceptionAtSafePoint` is called when any thread hits an HLE boundary. It checks:
```csharp
var threadHandle = GuestThreadExecution.CurrentGuestThreadHandle;
if (threadHandle == 0)
{
    threadHandle = _currentExternalGuestThreadHandle;
}
```

For the main thread:
- `CurrentGuestThreadHandle` = 0 (main thread)
- `_currentExternalGuestThreadHandle` = **GC thread's handle** (overwritten)
- Looks up `_pendingGuestExceptions[GC_thread_handle]` → NOT FOUND
- Main thread's pending exception (`_pendingGuestExceptions[main_thread_handle]`) is never consumed

## 14. shadPS4 REFERENCE FINDINGS

| Area | shadPS4 | SharpEmu |
|------|---------|----------|
| Thread representation | `pthread_t` = pointer to `ScePthread` struct | `pthread_t` = host heap pointer (`Marshal.AllocHGlobal`) |
| Thread identity lookup | Direct pointer dereference | Dictionary lookup (`_guestThreads`/`_externalGuestThreads`) |
| Exception delivery | Preemptive (POSIX signal) | Cooperative (waits for HLE safe point) |
| Register state preservation | Signal handler saves `mcontext_t` | `GuestCpuContinuation` struct |
| TLS initialization | `scePthreadAttrSetstack` + TCB setup | `TLS handler` setup during module loading |

**Key difference**: shadPS4 uses preemptive exception delivery (signal-based), while SharpEmu uses cooperative delivery (safe-point-based). The cooperative approach fails when the safe-point handle check uses a stale `_currentExternalGuestThreadHandle`.

## 18. EXACT NEXT EVIDENCE TARGET

**EXP-203 should fix `_currentExternalGuestThreadHandle` to be per-thread (e.g., `[ThreadLocal]` or stored per-host-thread) instead of a single static field.**

The fix:
1. Change `_currentExternalGuestThreadHandle` from `static ulong` to `[ThreadStatic] ulong` (or use a `Dictionary<int, ulong>` keyed by `Environment.CurrentManagedThreadId`)
2. This ensures each host thread has its own `_currentExternalGuestThreadHandle`
3. When the main thread hits a safe point, it will find its own handle (not the GC thread's)
4. The pending exception will be matched and delivered

**Validation**:
- After fix, `guest_exception.delivery_enter` should appear in the log
- `guest_exception.safe_point_enter` should appear
- Semaphore 0x83 should be signaled
- GC thread should resume
- Game should progress past the GC phase
