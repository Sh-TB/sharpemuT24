## Root Cause Analysis

### Between mkdir and semaphore creation:
1. `mkdir("/devlog")` → ALREADY_EXISTS
2. 38000+ mutex lock/unlock calls (IL2CPP type init)
3. `sema.create(0x7D)` through `sema.create(0x90)`
4. GC thread scheduled
5. `WaitSema(0x81)` → DEADLOCK

**There are NO HLE imports called between mkdir and semaphore creation** (other than the 38000+ mutex calls). This means the PlayerLoop registration code runs entirely in native code (inside Il2cppUserAssemblies.prx) without calling any HLE exports.

### The producer caller function (0x8001ED430) has zero references:
- Not called directly
- Not referenced by LEA
- Not referenced by RELA relocation
- Not in any data section

This means the function is either:
1. **Dead code** — the bootstrap job submission uses a different code path
2. **Called via C# delegate/function pointer** — the function pointer is set up at runtime by IL2CPP code
3. **Called via il2cpp_runtime_invoke** — the IL2CPP runtime invokes C# methods that call this function

### Most likely cause:
The Unity PlayerLoop initialization (which registers callbacks including the bootstrap job submitter) is **skipped or fails silently** inside the IL2CPP runtime. The IL2CPP runtime runs natively (no HLE interception), so we cannot see what happens inside.

The PlayerLoop registration likely depends on:
1. `il2cpp_runtime_invoke` — to call C# PlayerLoop setup methods
2. Correct IL2CPP metadata state — type definitions, method pointers
3. Correct initialization of the IL2CPP GC — which may not be fully functional
