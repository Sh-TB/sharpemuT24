  → skips +0xD3, +0x221, +0x24E (init write)
```

### Path That Reaches Init (EXPECTED)

```
+0x00: function entry
+0x8D: cmp r13d, 2             ; r13d >= 2
+0x91: jl NOT taken             ; continues
+0xD3: je NOT taken             ; rax != 2
+0x221: jne NOT taken           ; bl == 0

### Missing Condition

**r13d must be >= 2 for the init to execute.** Currently r13d = 1 (from ebx = 1).

The value of `ebx` at function entry is `0x00006FFDD0000000`. But `mov r13d, ebx` at +0x50 takes only the lower 32 bits, so `r13d = 0`. Wait — at the BP hit, `rbx=0x0000000000000001`. Let me check: `ebx` is the lower 32 bits of `rbx`. If `rbx=1`, then `ebx=1`, and `r13d=1`.

**r13d = 1 < 2 → jl taken → init skipped.**

## Answer

**The `jl` branch at 0x8013FCED1 (offset +0x91 in function 0x8013FCE40) is taken because `r13d < 2` (r13d = 1), causing execution to skip the init write at 0x8013FD08E.**

### Condition

```
+0x8D: cmp r13d, 2    ; r13d = 1 (from ebx via mov r13d, ebx at +0x50)
+0x91: jl 0x8013FCF55  ; TAKEN (1 < 2) → skips to +0x115, past init at +0x24E
```

### Root Cause Chain (Updated)

```
r13d = 1 (from ebx = 1 at function entry)
  → cmp r13d, 2 → 1 < 2
  → jl TAKEN → skip to +0x115
  → init write at +0x24E NEVER reached
  → [0x801E518C8] = 0 (NULL)
  → consumer 0x8013EB6B0 reads NULL → early exit
  → [0x801E51240] stays NULL
  → PlayerLoop skipped → WaitSema(0x81) deadlock
```

### Next Evidence Target

**What determines the value of `ebx` (and thus `r13d`) at function entry?** The value `ebx = 1` controls whether the init write executes. If `ebx >= 2`, the function would continue to the init write.

The value `ebx = 0x0000000000000001` at function entry comes from the caller. Finding why the caller passes `ebx = 1` instead of `ebx >= 2` will reveal the next link in the chain.
