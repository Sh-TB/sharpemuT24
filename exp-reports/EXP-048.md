# EXP-048 — Callback Stub-Ret + Broadened Investigation

## Date: 2026-07-30
## Status: PARTIAL — callback stubbed, il2cpp_init progresses, but crashes on other NULL metadata

---

## Executive Summary

Replaced all EXP-047 hacks with a single clean fix: **patch callback
`0x80134FA00` to return immediately** (`push rbp` → `mov al,1; ret`).
This makes the callback return success without executing, allowing
call #8 to continue.

**Result:** il2cpp_init **PROGRESSES** — Unity Job worker threads are
created (workers 0-7+). This is further than any previous experiment.
However, il2cpp_init still crashes due to **other NULL metadata pointers**
that are not yet set up. The SIGSEGV cascade eventually becomes fatal.

---

## Fix Applied

### Callback stub-ret (single clean fix)
```
0x80134FA00: push rbp (55) → mov al,1; ret; nop (B0 01 C3 90)
```

- Callback is called from call #8 but returns immediately with `al=1`
- Call #8 checks `al` → `al=1` (success) → real_init continues
- All EXP-047 hacks removed (flag, fake 0x801E51240, NOP call [rax])

### Key progress
- **il2cpp_init is PROGRESSING** — it creates Unity Job worker threads
- The callback stub-ret allows call #8 to return successfully
- real_init continues to calls #9+ which create workers
- Workers are scheduled with proper thread entry (0x800BB06A0)

### Remaining crash
The first SIGSEGV is at `0x8014327CF` (function `0x801431FB0`) which
reads `[NULL + 0xF4]`. This is a **different metadata pointer** (not
`0x801E51240`) that is also NULL because the metadata hasn't been
set up yet.

The crash chain:
```
il2cpp_init (real_init)
  → call #8 (0x804F23320) → callback stubbed (returns al=1)
  → call #9+ → creates Job workers
  → continues execution
  → calls 0x800C195C0 (from 0x8013F01FD)
    → calls 0x801431FB0
      → reads [NULL + 0xF4] → SIGSEGV → recovered
      → cascade of SIGSEGVs through 0x801434, 0x800C50B, 0x800B28A
      → eventually fatal crash at 0x80080684D (looping)
```

---

## Root Cause (Confirmed)

The metadata required by il2cpp_init is **not set up** before il2cpp_init
runs. On a real PS5, the metadata IS set up by a pre-init mechanism.
On SharpEmu, this mechanism is missing.

The callback stub-ret fix allows il2cpp_init to **progress further** than
ever before (creating worker threads), but it still crashes because other
metadata pointers are NULL.

## Next Step (EXP-049)

1. **Identify the NULL pointer at 0x8014327CF:** The crash reads
   `[NULL + 0xF4]`. Find which global/register holds the NULL pointer.
   This is a DIFFERENT metadata pointer from `0x801E51240`.

2. **Check if this metadata is also set by the hash lookup at 0x8013EEFE7:**
   The hash lookup sets `0x801E51240` but might also set other globals.
   If the hash lookup ran, it might set the pointer that's currently NULL.

3. **Make il2cpp_init return despite crashes:** The SIGSEGV recovery
   allows execution to continue. If enough SIGSEGVs are recovered,
   il2cpp_init might eventually return. Then the hash lookup would run,
   setting the metadata globals. Then subsequent calls would work.
   The current issue is that the SIGSEGV cascade becomes fatal before
   il2cpp_init returns.

4. **Investigate the fatal crash at 0x80080684D:** This is the
   non-recoverable SIGSEGV that kills the process. Find why it's
   non-recoverable and whether the recovery can be improved.
