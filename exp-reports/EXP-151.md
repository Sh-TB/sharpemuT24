## Confirmed Findings

### 1. Gate Function at 0x804FB8E60 — FULLY DECODED

```
0x804FB8E60: cmp byte [0x808D67B98], 0     ; check type initialized flag
0x804FB8E67: je +0x28 → 0x804FB8E91 (ret)  ; if 0 (not init), return early
0x804FB8E69: mov eax, 0x0F12                ; method token/hash
0x804FB8E6E: mov edx, 1                     ; bit to set
0x804FB8E73: lea rcx, [0x808B55698]         ; flag array base
0x804FB8E7A: BLSI rdi, rdi                  ; isolate lowest set bit
0x804FB8E7F: shr rdi, 12                    ; shift right 12
0x804FB8E83: BLSR rdx, rdx                  ; clear lowest set bit
0x804FB8E88: lock or [rcx+r8*8+0x464D8], rdx ; mark method as executed
0x804FB8E91: ret                            ; return
```

**This is the IL2CPP method execution tracker.** It:
- Checks if the type is initialized (byte at 0x808D67B98 != 0)
- If initialized, marks the method as "executed" in a flag array
- If NOT initialized (byte == 0), returns immediately without executing the method

### 2. Gate Byte is in BSS — Always 0

- **Gate byte address:** 0x808D67B98
- **PRX vaddr:** 0x4092B98
- **Location:** PRX BSS segment (vaddr 0x3C50000, memsz 0x444778, filesz 0x21CBC8)
- **File-backed range:** 0x3C50000 to 0x3E6CBC8
- **Byte vaddr 0x4092B98 > 0x3E6CBC8 → in BSS**
- **Runtime value:** Always 0x00 (BSS is zero-initialized)

### 3. No RELA Relocation Sets the Gate Byte

- Searched all RELA sections in the PRX
- **ZERO entries with r_offset matching 0x4092B98**
- No nearby entries within ±0x100 bytes
- The gate byte is NOT set by any relocation

### 4. No Code Writes to the Gate Byte

- Searched for `C6 05` (mov byte [rip+disp32], imm8) targeting 0x808D67B98 → ZERO matches
- Searched for `48/4C 89 05` (mov [rip+disp32], reg) targeting 0x808D67B98 → ZERO matches
- The gate byte is NEVER written by any code in the PRX

### 5. Gate Function Has 59,744 Callers

- Direct CALL callers of 0x804FB8E60: **5 callers**
- Callers of thunk 0x804FA6030 (which JMPs to gate): **59,744 callers**
- This is called from virtually every method in the PRX
- This is the standard IL2CPP "codegen initialize" pattern — every method checks if its type is initialized before executing

### 6. Flag Array is Also in BSS

- **Flag array base:** 0x808B55698 (BSS)
- **Flag array entries:** [base + r8*8 + 0x464D8] (BSS)
- All flag array entries are 0 at runtime

## Rejected Hypotheses

1. **"Gate at 0x804FB8E60 is a one-time init guard"** — REJECTED. It's called 59,744 times, not once. It's a per-method execution tracker.

2. **"RELA relocation should set the gate byte"** — REJECTED. No RELA entry exists for the gate byte address.

3. **"Code in the PRX writes to the gate byte"** — REJECTED. Zero write instructions target the gate byte.

4. **"Function pointer tables exist in PRX data"** — REJECTED. No arrays of 8+ consecutive code pointers found in data sections.

5. **"il2cpp_runtime_invoke is never referenced"** — REJECTED. LEA at 0x804ED7171 references the string, confirming the IL2CPP runtime invoke infrastructure exists.

## First Divergence Point

**The first incorrect state transition is the TYPE INITIALIZED FLAG not being set.**

```
Expected: .cctor runs → sets type flag to non-zero → gate allows method execution → PlayerLoop.Initialize runs
Actual:   .cctor runs → flag NOT set (stays 0) → gate blocks method execution → PlayerLoop.Initialize never runs
```

**The .cctor (static constructor) is called via `TryCallGuestFunction`, which has the EXP-138 RAX propagation bug.** The .cctor appears to return successfully (RAX=0), but the flag-setting code at the end of the .cctor is either:
- Skipped because RAX is not propagated correctly
- Or the .cctor's return value is checked and the flag is set conditionally

**Root Cause Chain:**
```
EXP-138 RAX propagation bug
  → .cctor called via TryCallGuestFunction, RAX not propagated
  → .cctor's flag-setting code fails or is skipped
  → Type initialized flag (0x808D67B98) stays 0
  → Gate function (0x804FB8E60) returns early for ALL methods
  → PlayerLoop.Initialize() method never executes
  → No PlayerLoop callbacks registered
  → No bootstrap job submitted
  → Dispatch loop blocks on WaitSema(0x81)
  → DEADLOCK
```

## Root Cause Probability

1. **EXP-138 RAX propagation bug prevents .cctor from setting type flag — 70% confidence**
   - The .cctor is called via TryCallGuestFunction
   - EXP-138 fix (raxCaptureSlot) is in source but NOT built/validated
   - If the fix works, .cctor will set the flag, and methods will execute
   - This explains ALL symptoms: gate returns early, PlayerLoop never runs, deadlock

2. **IL2CPP API function should set the gate byte but fails — 15% confidence**
   - A function called before the gate (during dt_init) might set the byte
   - If this function fails silently, the byte stays 0

3. **Gate byte is set by a different mechanism not yet identified — 10% confidence**
   - Could be set by IL2CPP metadata processing
   - Could be set by a native function we haven't analyzed

4. **Other unknown cause — 5% confidence**
