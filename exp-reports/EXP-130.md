# EXP-130 — Trace Producer Function Pointer Table

**Date:** 2026-08-04
**Status:** COMPLETE — ROOT CAUSE IDENTIFIED

## Finding

**The producer function `0x801028d80` is stored as a RELA relocation entry (r_addend=0x1028d80) targeting address `0x1cfccb0` (runtime `0x801cfccb0`) in a `[RW-]` data segment. The relocation was NEVER APPLIED — the target address contains `0x0` (NULL) instead of the producer's runtime address `0x801028d80`.**

**This is the root cause:** SharpEmu's dynamic linker did not apply this relocation. The function pointer that should point to the producer function is NULL. When the code that reads from `0x801cfccb0` and calls through it executes, it calls NULL — or more likely, the code that should read from this address checks it and skips the call because it's NULL.

## Evidence

### RELA entry

```
r_offset = 0x1cfccb0  (target: where the function pointer should be stored)
r_info   = 0x8         (sym=0, type=8 = R_X86_64_RELATIVE)
r_addend = 0x1028d80   (producer function offset from eboot base)
```

- **Relocation type 8** = `R_X86_64_RELATIVE` — the dynamic linker should write `base + r_addend` = `0x800000000 + 0x1028d80` = `0x801028d80` to address `0x801cfccb0`
- **Target address `0x801cfccb0`** is in a `[RW-]` (read-write) data segment
- **Current value at target: `0x0` (NULL)** — relocation was NOT applied

### Table structure

The relocation table is in a `[---]` LOAD segment (no permissions — metadata only) at file offset `0x1dfd970`, size `0x12fc30` (~77KB). This segment contains 51,842 entries (if 24 bytes each).

The entry containing the producer is at table offset `0xd5a70` (entry ~35,416).

### Why this matters

The producer function (`0x801028d80`) is the ONLY code that:
1. Writes to `[rbx+0x90]` (job queue counter)
2. Writes to `[rbx+0x88]` (semaphore handle)
3. Calls `SignalSema`

Without this function being called, semaphore 0x81 is never signaled, the main thread blocks forever, and the entire system deadlocks.

The function pointer at `0x801cfccb0` should be `0x801028d80` but is `0x0` because the relocation was not applied. Some code should read this pointer and call it — but since it's NULL, the call either doesn't happen or results in a NULL call.

## Confirmed

1. **Producer function pointer is stored as RELA relocation** — CONFIRMED (r_offset=0x1cfccb0, r_addend=0x1028d80, type=R_X86_64_RELATIVE)
2. **Relocation was NOT applied** — CONFIRMED (target address 0x801cfccb0 contains 0x0)
3. **Target is in a writable data segment** — CONFIRMED ([RW-] LOAD segment)
4. **Relocation type is R_X86_64_RELATIVE (type 8)** — CONFIRMED (simple base + addend relocation)

## Root Cause

**SharpEmu's dynamic linker did not apply the R_X86_64_RELATIVE relocation for the producer function pointer.** This is a relocation processing bug — the linker should have written `0x801028d80` to address `0x801cfccb0` during module loading, but it didn't.

This means the function pointer table entry that should invoke the producer is NULL, so the producer is never called, so semaphore 0x81 is never signaled, so the main thread blocks forever.
