## 2. Runtime Sequence

### argc=2 sequence:
```
1. INT3 installed at 0x8013ED057 (slot 1), 0x8013ED05D (slot 2), 0x804ED85D0 (slot 3)
2. Consumer reaches 0x8013ED057 (call [0x801ED6320])
   - [0x801E518C8] = 0x20000259C0 (NON-NULL)
   - [0x801E51240] = 0x0 (NULL)
   - [0x801ED6320] = 0x804ED85D0 (il2cpp_init)
3. Call executes → jumps to 0x804ED85D0 (il2cpp_init entry)
4. il2cpp_init executes
5. il2cpp_init does NOT return to 0x8013ED05D
6. Game enters dispatch loop → WaitSema(0x81) → DEADLOCK
```

### argc=1 sequence:
```
1. INT3 installed (same as argc=2)
2. Consumer reaches 0x8013ED057 (call [0x801ED6320])
   - [0x801E518C8] = 0x0 (NULL)
   - [0x801E51240] = 0x0 (NULL)
   - [0x801ED6320] = 0x804ED85D0 (il2cpp_init — SAME)
3. Call executes → jumps to 0x804ED85D0 (il2cpp_init entry)
4. il2cpp_init executes
5. il2cpp_init does NOT return
6. Game enters dispatch loop → WaitSema(0x81) → DEADLOCK
```

### Key difference: argc=1 vs argc=2
- `[0x801E518C8]`: NULL (argc=1) vs NON-NULL 0x20000259C0 (argc=2)
- `[0x801ED6320]`: SAME (0x804ED85D0 = il2cpp_init) in both cases
- il2cpp_init IS entered in both cases
- il2cpp_init does NOT return in either case
- Both reach WaitSema(0x81) deadlock

## 3. Exact Blocking Instruction

### The call at 0x8013ED057 is NOT the blocker — it executes correctly.

The actual blocking point is INSIDE `il2cpp_init` at `0x804ED85D0`. The function is entered but never returns. The exact instruction inside il2cpp_init that blocks is NOT YET IDENTIFIED — it requires tracing execution inside il2cpp_init.

### What we know:
- il2cpp_init entry: `0x804ED85D0` (first byte: `0x55` = push rbp)
- il2cpp_init does NOT return to `0x8013ED05D`
- The game eventually reaches WaitSema(0x81) at `0x800AA0207`

### What we don't know:
- Which instruction inside il2cpp_init blocks
- Whether il2cpp_init calls WaitSema directly or indirectly
- Whether il2cpp_init enters an infinite loop
- Whether il2cpp_init calls an unresolved import

## TASK 7 — Documentation: COMPLETED

### il2cpp_init lifecycle:
1. GOT writer 0x8013FB0B0 calls PLT 0x8019374D0 (NID r8mvOaWdi28) 232 times
2. First call resolves "il2cpp_init" → 0x804ED85D0, stored at [0x801ED6320]
3. Consumer 0x8013EB6B0 reaches call [0x801ED6320] at offset +0x19A7
4. il2cpp_init at 0x804ED85D0 is entered (RDI=0, no arguments)
5. il2cpp_init does NOT return
6. Game enters WaitSema(0x81) deadlock

### GOT/NID/PLT chain:
```
GOT writer 0x8013FB0B0
  → call PLT 0x8019374D0 (push 0xE7)
  → jmp [0x801D1ACE0] (DT_JMPREL entry 231)
  → NID r8mvOaWdi28 (il2cpp_api_lookup_symbol)
  → direct-bridged to native resolver at 0x804ED9B90 (when PRXs loaded)
  → resolver walks IL2CPP BST, returns 0x804ED85D0 for "il2cpp_init"
  → stored at [0x801ED6320]
```

### Blocking point:
- il2cpp_init at 0x804ED85D0 is entered but does NOT return
- The exact blocking instruction inside il2cpp_init is NOT YET IDENTIFIED
- Requires single-step trace inside il2cpp_init
