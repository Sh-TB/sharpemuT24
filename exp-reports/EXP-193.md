## 2. Exception Type

**No exception was thrown during normal DT_INIT execution.**

The `__cxa_throw` HLE was implemented but not triggered. The IL2CPP runtime's DT_INIT callbacks complete successfully without throwing exceptions.

The EXP-192 abort was an artifact of INT3 instrumentation, not a real runtime exception.

## 5. Newly Exposed Blocker

The crash is at `0x80080684D` (`mov r8d, [r15+rcx]` with `fault=0x0`) — the same crash as EXP-181.

This is the NULL pointer dereference in the Unity IL2CPP type metadata processing. The `[0x801E51240]` (Il2CppClass*) is still NULL because the IL2CPP API chain (`il2cpp_domain_get` → `il2cpp_class_from_name`) is not called before the crash function.

**The C++ exception ABI implementation did NOT change the runtime behavior** because no exceptions are thrown during normal DT_INIT. The __cxa_throw HLE is still valuable for future error paths but is not the current blocker.

## 6. EXP-192 Correction

**EXP-192's conclusion was WRONG.** The abort was NOT caused by missing `__cxa_throw` HLE. It was caused by INT3 instrumentation interference at the DT_INIT call rax instruction. The INT3 single-step re-patch mechanism corrupts the execution state when used on multi-byte instructions in certain contexts.

**Corrected root cause chain:**
```
EXP-192: INT3 at DT_INIT call rax → single-step corruption → wrong execution path → abort
EXP-193: Without INT3 → DT_INIT completes normally → crash at [0x801E51240]=NULL
```

## 7. Next Blocker

The crash at `0x80080684D` is the same NULL pointer issue from EXP-181:
- `[0x801E51240]` (Il2CppClass*) is NULL
- The IL2CPP API chain is never called before the crash
- The DT_INIT callback completes but doesn't set `[0x801E51240]`
- The consumer function's success path doesn't call `il2cpp_domain_get`

**The next investigation should focus on:**
1. Why the DT_INIT callback doesn't populate `[0x801E51240]`
2. Whether the IL2CPP runtime is fully initialized after DT_INIT
3. Whether `il2cpp_codegen_register` is called during DT_INIT (not just `il2cpp_init`)
