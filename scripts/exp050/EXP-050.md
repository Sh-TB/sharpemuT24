# EXP-050 — IL2CPP Initialization Ordering Investigation

## Date: 2026-07-30
## Status: PARTIAL — Multiple findings, hash lookup skip mechanism identified

---

## Executive Summary

Discovered the hash lookup at `0x8013EEFE0` is **skipped by 15+ conditional
jumps** in the init function between il2cpp_init return and the hash lookup.
The primary skip is at `0x8013EE0CE` (refcount check: `jle 0x8013EF25E`).
NOPping this jump didn't help because other jumps also skip.

Stubbing `0x800C195C0` (metadata accessor function) cleared the first cascade
(`0x8014327CF` gone) but a new cascade appeared at `0x8013F02C2` (init function
reads NULL metadata directly). Only 11 unique crash addresses in the cascade.

---

## Key Findings

### 1. Hash lookup skip mechanism
The hash lookup at `0x8013EEFE0` is **never reached** because 15+ conditional
jumps between il2cpp_init return (`0x8013ED05C`) and the hash lookup skip past
it. Key jumps:
```
0x8013EE0CE: jle 0x8013EF25E  (refcount <= 0 → skip)
0x8013EE1AE: jne 0x8013EF308  (skip)
0x8013EEB4F: jne 0x8013F58D1  (skip far)
0x8013EEABA: jne 0x8013EF061  (skip)
... (15 total)
```

NOPping one jump doesn't help — the code takes a different jump.
All jumps depend on metadata state that isn't set up on SharpEmu.

### 2. Metadata list population
- Only **1 write** to `[0x801EA4E80]` (by `0x800C66670`, creates initial empty list)
- Registration functions add entries to the list INSIDE the structure
- Initial node has flag `0x01` (initialized → lookup returns 0)
- Registration functions add nodes with flag `0x00` (not initialized → lookup searches)

### 3. Stub results
| Fix | First SIGSEGV | Total SIGSEGVs | Hash lookup |
|-----|--------------|----------------|-------------|
| Callback stub only (EXP-048) | 0x8014327CF | 226 | No |
| + NOP jump 0x8013EE0CE | 0x8014327CF | 226 | No |
| + Stub 0x800C195C0 | 0x8013F02C2 (NEW) | 226 | No |

Stubbing `0x800C195C0` **cleared the first cascade** (0x8014327CF gone) but
new cascade at `0x8013F02C2` (init function reads NULL metadata directly).

### 4. Unique crash addresses: 11
```
0x8013F02C2, 0x8013F02CF, 0x8013F02DD, 0x8013F02EB, 0x8013F02EE
0x8013F0311, 0x8013F0314, 0x8013F0334, 0x8013F0337
0x800C854B0, 0x800C854B8
+ 0x80080684D (fatal loop)
```

All in the init function (0x8013F02xx) or worker dispatch (0x800C854xx).
The init function reads NULL metadata at multiple points.

---

## Root Cause (Confirmed)

The init function has a complex control flow with 15+ conditional jumps that
skip the hash lookup when metadata isn't ready. On SharpEmu, the metadata
isn't ready (fields are NULL), so ALL jumps skip the hash lookup. The init
function then reads NULL metadata → SIGSEGV cascade.

On real PS5, the metadata IS ready (set by a mechanism SharpEmu doesn't
implement), so the jumps are NOT taken, the hash lookup runs, and the
metadata fields are set correctly.

## Next Step (EXP-051)

1. **Set ALL 255 metadata struct fields** to a properly formatted zero-filled
   buffer (NOT the struct base). Allocate a separate 64KB buffer, fill with
   zeros, and set all fields to point to it. This prevents SIGSEGVs without
   causing the hash table probe crash (EXP-049's mistake).

2. **NOP ALL 15+ conditional jumps** that skip the hash lookup. This is
   aggressive but ensures the hash lookup runs regardless of metadata state.

3. **Fix the fatal loop at 0x80080684D**: Cap the hash table probe iterations
   or detect the infinite loop and break out.
