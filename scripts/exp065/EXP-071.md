## Findings

### 1. [rbx+0x108] is a TAGGED POINTER, not a boolean flag

**Runtime value:** `0x00000006006D1101`

- Remove tag bit (low bit): `0x6006D1100`
- This is `rbx - 0x30` (48 bytes before the task descriptor)
- It's a pointer to a **dependency object** with the low bit set as a tag

The `cmp byte [rbx+0x108], 0` at `0x800AA0207` checks if the low byte is zero:
- Low byte = `0x01` (tagged pointer present) → `jne` skips SignalSema
- Low byte = `0x00` (no dependency) → falls through to SignalSema

### 2. CLEAR function (0x800A9F750) writes 0 to [rbx+0x108]

**Instruction:** `mov byte [rbx+0x108], 0x00` at `0x800A9F834`

This function would clear the dependency pointer, allowing SignalSema to be reached. But:

- **0 direct callers** (called via indirect dispatch)
- **0 occurrences in runtime log** — NEVER executed

### 3. SET function (0x800A9F9A0) sets [rbx+0x108] to 1

**Instruction:** `mov byte [rbx+0x108], 0x01` at `0x800A9FAED`

This function sets the dependency pointer (tagged). It's in the same function as the WaitSema call (`0x800A9FC20`). But also has **0 direct callers** and **0 log occurrences** — it's called indirectly.

### 4. All three functions (CLEAR, SET, WORKER) have 0 direct callers

All three are called via **indirect dispatch** (function pointers stored in the task descriptor):
- Worker entry: `0x800BB06A0` → calls WORKER function (`0x800AA0170`) via `[rbx+0x020]` or `[rbx+0x028]`
- SET function: called when a task is submitted with a dependency
- CLEAR function: called when the dependency is resolved (asset loaded, prerequisite task completed)

### 5. The dependency object at rbx-0x30

The tagged pointer `0x6006D1100` (= `rbx - 0x30`) points to an object 48 bytes before the task descriptor. This is likely a **dependency tracker** or **continuation object** that tracks whether the task's prerequisites are met.

Since no assets are loaded and no prerequisite tasks complete, the dependency is never resolved, the CLEAR function is never called, and `[rbx+0x108]` stays as a non-zero tagged pointer.

## Root Cause (Complete Chain)

```
Unity creates worker pool with task descriptors
↓
Task descriptors have dependency pointers at [rbx+0x108]
↓
Dependency = tagged pointer to unresolved object (0x6006D1101)
↓
Worker checks: byte [rbx+0x108] == 0?
↓
NO (0x01, tagged pointer present) → jne skips SignalSema
↓
Worker loops back → checks [rbx+0xf8] (task function pointer) → NULL
↓
Worker calls NULL → TryRecoverNullExecuteFault → loops
↓
1000+ recoveries → host stack corruption → SIGABRT
```

**The dependency at `[rbx+0x108]` is never resolved because:**
1. The CLEAR function (`0x800A9F750`) is never called
2. It would be called when a dependency (asset load, prerequisite task) completes
3. No dependencies complete because the main thread doesn't progress far enough
4. The main thread doesn't progress because... (this is the next question)
