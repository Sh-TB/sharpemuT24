## Task 4: Root Cause — FAST_PATH=0 Blocks Main Thread

**CONFIRMED:** With `FAST_PATH=0`, the main thread blocks on its own `sceKernelWaitSema` call (handle 0x83). The code that should call `sceKernelSignalSema` is AFTER the main thread's wait — it's a chicken-and-egg problem. The main thread needs to progress past its own wait to signal workers.

**With `FAST_PATH=1`:** All `sceKernelWaitSema` calls return immediately, allowing the main thread to progress and continue Unity runtime initialization.
