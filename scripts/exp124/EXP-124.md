# EXP-124 — Main Thread Job Dispatch Investigation

**Date:** 2026-08-03
**Status:** COMPLETE — BREAKTHROUGH
**Goal:** Find why the main thread never submits the first worker job.

---

## Finding

**The main thread is BLOCKED on `WaitSema(0x81)` — a "Baselib_SystemSemaphore" that is NEVER signaled.** The main thread is not in a "busy loop" as previously thought (CHECKPOINT section 15). It is blocked on a semaphore wait at `0x804F6E9E6` (return address `0x804F6E9EB`) in Il2cppUserAssemblies.prx.

**This is the immediate cause of the entire system deadlock:** The main thread cannot dispatch tasks to workers because it is itself blocked waiting on a semaphore that nobody signals. Handle 0x81 is a "Baselib_SystemSemaphore" (init=0, max=2147483647) — created with initial count 0 and never signaled.

**The complete deadlock chain:**
1. Main thread blocks on `WaitSema(0x81)` at `0x804F6E9E6` → cannot dispatch tasks
2. Workers block on `WaitSema(0x5C-0x74)` (EVEN handles) → waiting for tasks that never come
3. IL2CPP GC thread blocks on `WaitSema(0x83)` (SuspendSemaphore) → waiting for GC work
4. Nobody signals ANY of these semaphores → system-wide deadlock

```

2. Workers created (13 × AssetGarbageCollectorHelper)

4. Main thread enters job dispatch function at ~0x804F6E960
```

## Callback/Event Findings

The main thread's `WaitSema(0x81)` is in a **job dispatch/scheduling function** at `0x804F6E960` in the PRX. The function:
1. Tries to atomically grab work from a queue (`lock xadd [r14+0x90]`)
2. If no work available, blocks on WaitSema(`[r14+0x88]` = handle 0x81)
3. After wake, processes work items

**What should signal handle 0x81:** The code that submits work to the main thread's job queue. In Unity, this would be triggered by:
- A timer/vblank/flip event callback
- An async IO completion
- A graphics subsystem callback
- A pthread_cond_signal equivalent

**SharpEmu may be missing the HLE primitive that should fire this signal.** This is the specific question for maintainers.
