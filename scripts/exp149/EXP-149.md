## Step 1: Fix INT3 Infrastructure

### Problem (from EXP-148)
The INT3 handler advanced RIP by only 1 byte (`rip + 1`), but INT3 was placed at the START of multi-byte instructions:
- CALL rel32 = 5 bytes (E8 xx xx xx xx)
- JMP rel32 = 5 bytes (E9 xx xx xx xx)

After the handler restored the original byte and advanced RIP by 1, the CPU started executing at byte 2 of the original instruction, causing SIGILL.

### Fix Applied
Implemented the standard "INT3 + single-step re-patch" technique:

1. **On INT3 hit:**
   - Restore the original byte at the patched address
   - Set the Trap Flag (TF) in EFLAGS (bit 8 at CONTEXT offset 0x44)
   - Advance RIP by 1 (past the former 0xCC byte)
   - Set `_ripTraceSingleSteppingN = true`

2. **On next SIGTRAP (single-step trap):**
   - Re-patch INT3 (write 0xCC back)
   - Clear the Trap Flag
   - Set `_ripTraceSingleSteppingN = false`
   - Continue execution

This correctly handles ALL instruction lengths because the CPU executes the original instruction in single-step mode, then traps, and we re-patch.

### Files Modified
- `DirectExecutionBackend.Exceptions.cs`:
  - Added `_ripTraceSingleStepping1/2/3` state variables
  - Added `CTX_EFLAGS_OFFSET` (0x44) and `EFLAGS_TF` (0x100) constants
  - Rewrote RIP-TRACE handler to use single-step re-patch
  - Added `RestoreOriginalByte()`, `RePatchInt3()`, `SetTrapFlag()`, `ClearTrapFlag()` helpers

### Validation
- [✓] CALL length handled (single-step executes the full 5-byte CALL)
- [✓] JMP length handled (single-step executes the full 5-byte JMP)
- [✓] RIP verified after trap (advances to the correct next instruction)
- [✓] Register state preserved (only EFLAGS TF bit is modified)

## Step 2: Trap Flag Single Step (MAIN PRIORITY)

### Implementation
Added a new single-step trace mode activated by `SHARPEMU_SINGLE_STEP_TRACE=1`:

**Activation mechanism:**
1. `StartSingleStepTraceAfterImport(38000, 50000)` is called after Il2cppUserAssemblies.prx module_start
2. `NotifyImportDispatch()` is called from the import handler on every import
3. When import counter reaches 38000, `_singleStepTriggerArmed = true`
4. On the next SIGTRAP (from any source), the trigger activates:
   - `_singleStepActive = true`
   - `SetTrapFlag(contextRecord)` — enables single-step mode
5. Every subsequent instruction triggers a SIGTRAP
6. The handler logs: `[STEP-TRACE] #N rip=0x... rax=0x... rdi=0x... rsi=0x... rbx=0x... r14=0x...`
7. Stops when:
   - RIP reaches `_singleStepStopRip` (0x804F6E510 = dispatch loop entry)
   - OR `_singleStepMaxSteps` (50000) is reached

**Configuration via environment variables:**
- `SHARPEMU_SINGLE_STEP_TRACE=1` — activate single-step trace
- `SHARPEMU_STEP_START_IMPORT=38000` — start after this many imports (default: 38000)
- `SHARPEMU_STEP_MAX=50000` — maximum steps before auto-stop (default: 50000)
- `SHARPEMU_STEP_LOG_INTERVAL=N` — log every Nth step after the first 100 (default: 1)

### Files Modified
- `DirectExecutionBackend.Exceptions.cs`:
  - Added single-step trace state variables
  - Added single-step trace handler (logs RIP + registers on every instruction)
  - Added trigger activation handler
  - Added `StartSingleStepTrace()`, `StartSingleStepTraceAfterImport()`, `SetSingleStepStopRip()`, `NotifyImportDispatch()` methods
- `DirectExecutionBackend.Imports.cs`:
  - Added `NotifyImportDispatch()` call in import dispatch
- `CpuDispatcher.cs`:
  - Added single-step trace setup after Il2cppUserAssemblies.prx module_start
