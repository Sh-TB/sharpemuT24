## Caller: 0x800000070 (eboot main entry)

## Parent: 0x8013FCE40

## RBX source: NOT from function arguments directly

RBX is modified INSIDE the function at +0x22: `mov ebx, edi`

The chain is:
```
eboot main receives rdi = pointer to args structure
  → r14d = [rdi] = 1 (argc = 1, single program path)
  → rdi = r14 (passes as first arg to 0x8013FCE40)
  → call 0x8013FCE40
    → +0x22: mov ebx, edi → ebx = 1 (lower 32 bits of rdi)
    → +0x50: mov r13d, ebx → r13d = 1

```

## r13d at jl branch: 1 (from mov r13d, ebx at +0x50)

## Branch: taken (jl at +0x91, r13d=1 < 2)

## Init write: 0x8013FD08E — NO (never reached)

## Hypothesis: CONFIRMED

The branch condition r13d < 2 is confirmed as the blocker. The value r13d = 1 comes from `edi` (the first argument to function 0x8013FCE40), which is set by the caller (eboot main) from `[rdi]` — the first dword of the arguments structure passed to main by the PS5 loader. This value is `argc = 1` (the program was launched with a single argument — the program path itself).

The function 0x8013FCE40 uses this value as a mode/level selector: `cmp r13d, 2; jl` means "if mode < 2, skip initialization." On PS5, argc=1 is normal, but the function expects mode >= 2 to perform initialization. This suggests the function is designed to be called with a specific mode parameter (not argc), and the caller is passing the wrong value.

## Next evidence target:

What is the expected value of the first argument to 0x8013FCE40? The function expects rdi >= 2 to reach the init write. The caller (eboot main at 0x800000070) passes r14 = [rdi] = 1 (argc). The question is: should the caller pass a different value (e.g., a mode flag or initialization level), or should the function handle argc=1 differently?

This may be a PS5-specific initialization protocol where the loader passes a structure with initialization level/flags, and SharpEmu's loader passes argc=1 instead of the expected initialization level.
