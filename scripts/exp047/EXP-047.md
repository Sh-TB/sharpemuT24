# EXP-047 — IL2CPP Initialization Order Fix

## Date: 2026-07-30
## Status: PARTIAL — callback crash prevented, cascade remains

---

## Executive Summary

Applied three fixes to prevent the metadata callback crash:
1. Set metadata flag `[rdx+0x19] = 1` → lookup returns 0 (matching real PS5)
2. Set `0x801E51240 = 0x801E50E40` (valid readable address, prevents SIGSEGV)
3. NOP `call [rax]` at `0x80134FA7D` (prevents NULL function call)

**Results:**
- ✅ 0 crash function calls (0x80135DDD0 never called)
- ✅ 0 NULL execute faults
- ✅ Call [0] at 0x80134FA7D successfully NOPped
- ❌ 226 SIGSEGV signals from cascade through 0x8014327CF etc.
- ❌ Hash lookup at 0x8013EEFE0 never reached
- ❌ Fatal crash at same final location

NOPping call #8 (skipping the entire callback) reduces SIGSEGVs to 32
but causes calls #16/#17 to crash (they depend on call #8's setup).

## Fix Details

### Fix 1: Metadata flag = 1
```
[EXP047-FIX] Set metadata flag at 0x60011BD69 = 1 (was 0)
```
Forces `0x800C66B40` to return 0 (early exit instead of search).
Matches real PS5 where the metadata list is empty at this point.

### Fix 2: 0x801E51240 = 0x801E50E40
```
[EXP047-FIX] Set 0x801E51240 = 0x801E50E40 (metadata struct base)
```
Provides a valid readable address so reads at `[rax+0x90]`, `[rax+0x98]`,
`[rax+0xa0]` return 0 instead of SIGSEGV. The struct is zeroed by
the once-init callback, so all fields are 0.

### Fix 3: NOP call [rax] at 0x80134FA7D
```
[EXP047-FIX] NOPped call [rax] at 0x80134FA7D (FF 10 -> 90 90)
```
Prevents the NULL function call after the metadata lookup returns 0.
The callback continues without calling the crash function.

## Remaining Issue

After the NOPped `call [rax]`, the callback `0x80134FA00` continues
to call `0x801352760` and other functions. These functions read from
metadata pointers that are NULL or zero. The SIGSEGV recovery handles
each one (sets dest=0, skips), but the cascade eventually reaches a
non-recoverable crash at `0x80080684D` (looping SIGSEGVs).

The callback is **not designed** to handle the case where the metadata
lookup returns 0. It assumes the lookup always succeeds and the returned
object has valid data.

On a real PS5, the callback is **not called at all** during il2cpp_init.
The metadata list is empty, the lookup returns 0, and the PS5 kernel
handles the NULL call by killing the thread or returning to the caller
in a way that doesn't cascade.

### NOP call #8 test
NOPping call #8 entirely (skipping the callback) reduces SIGSEGVs from
226 to 32, but calls #16/#17 crash because they depend on call #8's
setup code. The setup code (before the callback) is needed by later
calls.

---

## Root Cause (Final)

The metadata list at `[0x801EA4E80]` is populated prematurely on
SharpEmu because registration functions run during the init function's
first-time path. On a real PS5, the list should be empty at this point.

The metadata lookup finds entries and returns non-zero. The callback
calls the returned function, which reads `0x801E51240 = 0` → crash.

The registration functions run too early because SharpEmu executes
the eboot DT_INIT's fini_array (which contains registration functions)
at startup time. On a real PS5, the fini_array might also run at
startup, but the registration functions might not add entries to the
**metadata list** at `[0x801EA4E80]` — they might add to a different
list or with different timing.
