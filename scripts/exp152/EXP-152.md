## Flag Lifecycle

### Created:
- **Address:** 0x808D67B98
- **Location:** PRX BSS segment (vaddr 0x3C50000, memsz 0x444778, filesz 0x21CBC8)
- **Initial value:** 0x00 (BSS zero-initialization)
- **Owner:** IL2CPP type initialization system

### Read:
- **53 CMP instructions** check `byte [0x808D67B98]` against 0
- **Primary reader:** Gate function at 0x804FB8E60 (called 59,744 times via thunk 0x804FA6030)
- **Purpose:** Check if a type is initialized before executing its methods
- **Logic:** `if (flag == 0) return early; else run method`

### Written:
- **3 MOV DWORD instructions** write value 1 to the flag
- **Writer 1:** 0x804FB1C1B in function 0x804FB1B90
  - Function checks flag at offset +0x5: `cmp byte [0x808D67B98], 0; je +2 → ret`
  - If flag == 0: return early (DON'T write)
  - If flag != 0: continue, eventually write 1
- **Writer 2:** 0x804FBF45B in function 0x804FBF250
  - Same pattern: checks flag at offset +0x90, skips if 0
- **Writer 3:** 0x804FBF509 in function 0x804FBF250
  - Same function as Writer 2, same guard

### Consumed:
- **Gate function** at 0x804FB8E60 uses the flag to decide whether to execute IL2CPP-generated methods
- **59,744 callers** invoke the gate before running their methods
- **Result:** Since flag is always 0, ALL methods are skipped → PlayerLoop.Initialize never runs → deadlock

## Root Cause Status

**Root Cause: CONFIRMED — Chicken-and-egg guard prevents flag from ever being set**

**Confidence: 85%**

### Evidence:

1. **All 3 writer functions check the flag BEFORE writing it:**
   - Function 0x804FB1B90: `cmp byte [0x808D67B98], 0; je +2 → ret` at offset +0x5
   - Function 0x804FBF250: `cmp byte [0x808D67B98], 0; je +43 → skip` at offset +0x90
   - If flag == 0, the write instruction is NEVER reached

2. **No unconditional writer exists:**
   - Searched entire PRX for RIP-relative writes to 0x808D67B98 → only 3 found, all guarded
   - Searched for LEA loading flag address → 0 found
   - Searched for MOV imm64 with flag address → 0 found
   - Searched data sections for flag address as 64-bit constant → 0 found
   - Searched RELA relocations → 0 found

3. **The flag is NEVER set at runtime:**
   - BSS initialization sets it to 0
   - No code ever changes it to non-zero
   - The gate function always takes the `je` branch (skip method)

4. **Writer function IS reachable from dt_init:**
   - Call chain: dt_init → 0x804F64550 → 0x804CE1CE0 → 0x804FA2700 → 0x804F51FE0 → 0x804FBF1A0 → 0x804FB1B90
   - But the writer function checks the flag and returns early if 0

### The Chicken-and-Egg Problem

```
Flag starts at 0 (BSS)
  ↓
Gate function checks flag → flag == 0 → skip methods
  ↓
Writer function checks flag → flag == 0 → return early (DON'T set)
  ↓
Flag stays 0 forever
  ↓
ALL IL2CPP methods are skipped
  ↓
PlayerLoop.Initialize() never runs
  ↓
No bootstrap job → WaitSema(0x81) → DEADLOCK
```

### What SHOULD Set the Flag Initially?

The flag must be set by a mechanism that does NOT check the flag first. Possible candidates:

1. **IL2CPP type initializer (.cctor)** — The .cctor should set the flag after initializing the type. But the .cctor itself might be guarded by a different flag or called via TryCallGuestFunction.

2. **IL2CPP metadata processing** — During `il2cpp_init`, the runtime might process type definitions and set initialization flags. This would be C code in the IL2CPP runtime, not generated code.

3. **An HLE function SharpEmu doesn't implement** — A PS5 system function that initializes IL2CPP type metadata.

4. **A different flag controls the writer** — The writer functions check TWO flags:
   - Writer 1 (0x804FB1B90): checks `byte [0x808D67B98]` AND `byte [0x808A75690]`
   - The second flag at 0x808A75690 is also 0 in the file (but file-backed, not BSS)
   - If the second flag should be non-zero, the writer might proceed

## Writer Function Deep Analysis

### Writer Function 1: 0x804FB1B90

```asm
0x804FB1B90: push rbp
0x804FB1B91: mov rbp, rsp
0x804FB1B94: cmp byte [0x808D67B98], 0    ; CHECK FLAG
0x804FB1B9B: je +2 → 0x804FB1B9E           ; if 0, return early
0x804FB1B9D: pop rbp
0x804FB1B9E: ret                            ; *** RETURNS WITHOUT SETTING FLAG ***
...
0x804FB1C05: cmp byte [0x808D67B98], 0    ; CHECK FLAG AGAIN
0x804FB1C0C: je +0x17                       ; if 0, skip
0x804FB1C0E: cmp byte [0x808A75690], 2    ; CHECK SECOND FLAG
0x804FB1C15: je +0xDA                       ; if == 2, skip
0x804FB1C1B: mov dword [0x808D67B98], 1    ; *** SET FLAG TO 1 ***
0x804FB1C25: call ...
```

**Logic:**
1. First check at function entry: if flag == 0, return immediately (DON'T set)
2. Second check later: if flag == 0, skip the set
3. Third check: if second flag (0x808A75690) == 2, skip the set
4. Only if ALL checks pass: set flag to 1

**The function is its own guard!** It checks the flag at the very start and returns early if 0. This means the flag can NEVER be set by this function if it starts at 0.

### Writer Function 2: 0x804FBF250

```asm
0x804FBF250: push rbp
0x804FBF251: mov rbp, rsp
0x804FBF253: push rbx
0x804FBF254: push rax
0x804FBF255: cmp byte [0x808D67B98], 0    ; CHECK FLAG (different address calculation)
0x804FBF25C: jne +0x11D                     ; if != 0, skip to later code
...
0x804FBF2E0: cmp byte [0x808D67B98], 0    ; CHECK FLAG AGAIN
0x804FBF2E7: je +0x2B                       ; if 0, skip
...
0x804FBF45B: mov dword [0x808D67B98], 1    ; *** SET FLAG TO 1 ***
```

Same pattern — checks the flag before setting it.

## EXP-138 Hypothesis Validation

### Previous hypothesis (EXP-151):
"EXP-138 RAX propagation bug prevents .cctor from setting type flag"

### EXP-152 finding:
**REJECTED as the PRIMARY cause.** The flag is NOT set by the .cctor via TryCallGuestFunction. The flag is set by 3 specific MOV instructions in the PRX, all of which check the flag before writing. The .cctor is not involved in setting this particular flag.

### However, EXP-138 may still be relevant:
The writer function 0x804FB1B90 is reachable from dt_init via a 6-step call chain. If any function in this chain is called via TryCallGuestFunction and RAX is not propagated, the call might fail silently, preventing the writer from being reached. But the writer itself has a chicken-and-egg guard that would prevent the flag from being set even if the function IS reached.

### Revised root cause:
The flag is NEVER set because:
1. The writer functions check the flag before setting it
2. If flag == 0, the writer returns early
3. No unconditional setter exists
4. The flag starts at 0 (BSS) and stays 0

This is NOT an EXP-138 issue. This is a **missing initialization step** — something that should set the flag BEFORE the gate and writer functions are called.

## What Should Set the Flag?

### On real PS5:
The flag at 0x808D67B98 is likely set by **il2cpp_runtime_class_init** or equivalent IL2CPP runtime C code. This function:
1. Is called when a type is first accessed
2. Runs the type's .cctor (static constructor)
3. Sets the "type initialized" flag to non-zero
4. Returns

On SharpEmu, this function might:
1. Not be implemented (HLE stub returns without setting flag)
2. Be implemented but fail to set the flag
3. Be called but the .cctor fails (EXP-138 could affect this)

### The key question:
**Does SharpEmu implement `il2cpp_runtime_class_init` or equivalent?**

This is the function that should:
1. Check if a type is initialized
2. If not, run the .cctor
3. Set the initialization flag
4. Return

If SharpEmu doesn't implement this, or implements it incorrectly, the flag is never set.
