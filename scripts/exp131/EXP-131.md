# EXP-131 — RELA Relocation Processing Audit

**Date:** 2026-08-04
**Status:** COMPLETE — ROOT CAUSE CONFIRMED

## Finding

**SharpEmu's `TryLoadTableBytes` fails to load the RELA relocation table because the table is in a `[---]` (no-permissions) PT_LOAD segment.** All three fallback paths in `TryLoadTableBytes` fail:

1. `virtualMemory.TryRead(guestAddr)` — FAILS: segment has no permissions (flags=0), not mapped as readable
2. `virtualMemory.TryRead(location)` — FAILS: `0x1f435f0` is not a valid runtime address
3. `elfData.Slice((int)location, (int)size)` — FAILS: `location` (0x1f435f0 = 32781808) > `elfData.Length` (32697964 = 0x1f2ee6c)

The actual file offset for the RELA data is `0x1e075f0` (computed from `p_vaddr` → `p_offset` mapping), which IS within the file. But `TryLoadTableBytes` uses the DT_RELA value (a vaddr) directly as a file offset in the third fallback, which fails because the vaddr doesn't equal the file offset for this segment.

**This means ALL 49,850 RELA relocations are skipped — not just the producer pointer.** This is a systemic failure, not a single-entry bug. However, working games (Dreaming Sarah, Arise) boot fine because they likely have their RELA tables in segments with permissions, or use a different ELF layout.

## Evidence

### ELF segment layout

| Segment | Flags | vaddr range | Contains RELA? |
|---------|-------|-------------|----------------|
| [--X] | Exec | 0x0 - 0x1938c2c | No |
| [R--] | Read-only | 0x193c000 - 0x1c7ed80 | No |
| [RW-] | Read-write | 0x1c80000 - 0x1d1c450 | No |
| [RW-] | Read-write (BSS) | 0x1d20000 - 0x1df5d78 | No |
| **[---]** | **No permissions** | **0x1f39970 - 0x20695a0** | **YES — RELA table** |

### RELA table details

- DT_RELA = 0x1f435f0 (vaddr, in [---] segment)
- DT_RELASZ = 0x124170 (1,196,400 bytes, 49,850 entries)
- File offset (computed): 0x1e075f0
- File offset + size: 0x1f2b760 (fits in file: file size = 0x1f2ee6c)

### TryLoadTableBytes failure path

```csharp
// Fallback 1: read from guest memory at vaddr + imageBase
guestAddr = 0x1f435f0 + 0x800000000 = 0x801f435f0
virtualMemory.TryRead(guestAddr, tableBytes) → FAILS (segment not mapped)

// Fallback 2: read from absolute guest address
virtualMemory.TryRead(0x1f435f0, tableBytes) → FAILS (not a valid address)

// Fallback 3: read from elfData as file offset
location = 0x1f435f0 (32781808)
elfData.Length = 32697964 (0x1f2ee6c)
32781808 > 32697964 → FAILS
```

### The producer's RELA entry (index 34794 of 49850)

```
r_offset = 0x1cfccb0 (target in [RW-] segment)
r_info = 0x8 (type = R_X86_64_RELATIVE)
r_addend = 0x1028d80 (producer function offset)
```

This entry IS in the RELA table but is NEVER PROCESSED because the entire table fails to load.

### Code path

1. `SelfLoader.LoadCore()` calls `ResolveAndPatchImportStubs()`
2. `ResolveAndPatchImportStubs()` calls `ParseDynamicInfo()` → gets `RelaOffset=0x1f435f0`, `RelaSize=0x124170`
3. Calls `TryLoadTableBytes(elfData, virtualMemory, imageBase, 0x1f435f0, 0x124170, out relaBytes)`
4. `TryLoadTableBytes` tries 3 fallbacks — ALL FAIL
5. RELA relocations are never collected → `relocations.Count` stays at whatever JMPREL contributes (600 entries)
6. 49,850 RELA entries (including the producer pointer) are NEVER applied

### SelfLoader.cs confirms RELATIVE relocations ARE supported

Lines 928-935 show that `RelocationTypeRelative` relocations ARE added as descriptors and would be applied if they reached `AppendRelocationDescriptors`. The bug is that they NEVER reach it because the RELA table itself fails to load.

## Files Changed

**No files changed yet.** The fix requires modifying `TryLoadTableBytes` to correctly resolve vaddr → file offset for segments where `p_vaddr != p_offset`.

## Tests Executed

1. **TEST A (relocation code audit):** SharpEmu DOES support R_X86_64_RELATIVE (type 8) — it creates descriptors and applies them. The code is correct.
2. **TEST B (failed relocations count):** ALL 49,850 RELA entries fail to load. Not just the producer — the entire RELA table is skipped.
3. **TEST C (producer pointer verification):** The RELA entry for the producer IS in the DT_RELA table at index 34794. Target address `0x1cfccb0` contains `0x0` (NULL) because the relocation was never applied.
4. **TEST D/E (fix and re-run):** Cannot execute — no dotnet SDK available.
