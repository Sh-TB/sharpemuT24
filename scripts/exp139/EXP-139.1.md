# EXP-139.1 — Yatzi .NET 10 Nested CallNativeEntry Blocker

**Date:** 2026-08-04
**Commit tested:** `a8a6a23` + Experiment D changes (not yet committed)
**Game:** Yatzi (PPSA17697)
**Status:** PARTIAL — .NET 10 "Invalid Program" crash RESOLVED, but IL2CPP resolver returns 0

---

## 1. Hypothesis

**H1:** The .NET 10 "Invalid Program: attempted to call a UnmanagedCallersOnly method from managed code" crash is caused by nested `CallNativeEntry` calls (managed→native→managed→native). Skipping the nested call will allow Yatzi to progress past the crash point.

**H2 (rejected):** Adding `[UnmanagedCallersOnly]` to `CallNativeEntry` would fix the crash. REJECTED — `[UnmanagedCallersOnly]` methods cannot be called directly from managed code (CS8901).

---

## 2. Change

### Experiment B (REJECTED)
- **Change:** Add `[UnmanagedCallersOnly(CallConvs = new[] { typeof(CallConvCdecl) })]` to `CallNativeEntry`
- **Result:** Build FAILED — CS8901: cannot be called directly from managed code
- **Action:** Reverted

### Experiment D (APPLIED)
Two changes, applied ONE AT A TIME:

#### Change 1: `CxxAbiExports.cs` — Skip nested `TryCallGuestFunction` in `ExecuteOnce`
```csharp
bool skipNestedCall = true;  // EXP-139.1: set to false to restore original behavior
if (!skipNestedCall && scheduler is not null && callbackAddress != 0)
```
- **Purpose:** Avoid nested `CallNativeEntry` from `ExecuteOnce` HLE export
- **Effect:** `std::_Execute_once` marks flag as complete without calling the guest callback

#### Change 2: `DirectExecutionBackend.Imports.cs` — Skip nested `TryCallGuestFunction` in `DispatchIl2CppApiLookupSymbol`
```csharp
bool skipNestedResolverCall = true;  // EXP-139.1: diagnostic
if (!skipNestedResolverCall && scheduler != null)
```
- **Purpose:** Avoid nested `CallNativeEntry` from IL2CPP resolver
- **Effect:** Resolver returns 0 for ALL il2cpp_* symbols (same as EXP-026 "232 NULL returns")

## 6. PASS/FAIL/BLOCKED

**Status: BLOCKED**

- ✅ .NET 10 "Invalid Program" crash: RESOLVED (by skipping nested calls)
- ✅ Dreaming Sarah Golden Gate: PASS (no regression)
- ✅ Yatzi progresses further (466 resolver entries vs 1)
- ❌ IL2CPP resolver returns 0 for ALL symbols (no IL2CPP API available)
- ❌ Yatzi still crashes (SIGSEGV when guest uses NULL function pointer)
- ⚠️ EXP-138 RAX propagation fix: STILL NOT VALIDATED (nested call was skipped)

### What this proves
1. The .NET 10 crash IS caused by nested `CallNativeEntry` calls
2. Skipping nested calls allows Yatzi to progress past the crash
3. But without the nested call, the IL2CPP resolver cannot run
4. EXP-138's RAX fix is in the nested call path — it cannot be validated while the nested call is skipped

### What is needed
A mechanism to run the nested guest function WITHOUT calling `CallNativeEntry` from within the managed import dispatch path. Options:
1. **Run nested guest function on a separate OS thread** (like `NativeGuestExecutor` does on Windows)
2. **Use `Thread.Start` with a native delegate** to avoid the managed→native→managed→native chain
3. **Restructure `DispatchIl2CppApiLookupSymbol` to defer the resolver call** to the main execution loop
