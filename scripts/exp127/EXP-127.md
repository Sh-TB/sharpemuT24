# EXP-127 — Multi-Hypothesis Investigation

**Date:** 2026-08-04
**Status:** COMPLETE

## Finding

**The producer code EXISTS in eboot.bin (459 SignalSema callers) but is NEVER REACHED because the main thread blocks on WaitSema(0x81) before reaching the bootstrap job submission code.** This is a bootstrap problem — the main thread enters the Unity Job System dispatch loop before Unity's initialization submits the first job.

The SignalSema wrapper in Il2cppUserAssemblies.prx (0x804fc1c74) has **0 callers**. The PRX never calls SignalSema directly. All signaling goes through eboot.bin's 459 SignalSema call sites, but the main thread blocks before reaching any of them.

**HLE is correct** — SignalSema and WaitSema work properly. The issue is that the game code never calls the producer.

## Tests Executed

### TEST A — Wider producer search (ALL 8 PRX modules)
- Searched all PRX modules for lock xadd/inc/add [reg+0x90] and [reg+0x88]
- **RESULT: ZERO producer increments in ANY PRX module**
- SignalSema wrapper in PRX (0x804fc1c74) has 0 callers
- PRX never calls SignalSema directly

### TEST B — SharpEmu HLE analysis
- B1: SignalSema wakes both host-thread (Monitor.PulseAll) and guest-thread (WakeBlockedDirectories) waiters — CORRECT
- B2: SignalSema reaches correct semaphore by handle lookup — CORRECT
- B3: Host-thread wait uses Monitor.Wait(100ms) — CORRECT
- B4: Semaphore with count=0 CAN be signaled — CORRECT
- **HLE verdict: CORRECT. Not an HLE bug.**
