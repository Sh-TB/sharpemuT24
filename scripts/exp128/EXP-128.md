# EXP-128 — Bootstrap Initialization Gap Analysis

**Date:** 2026-08-04
**Status:** COMPLETE

---

## Finding

**The main thread's execution between worker creation and WaitSema(0x81) block is entirely consumed by Unity's IL2CPP initialization sequence (real_init).** The main thread does NOT skip any initialization step — it runs real_init's full call chain, creates the job queue (handle 0x81), creates the GC thread, then immediately enters the job dispatch loop and blocks because no job has been submitted yet.

**The bootstrap job should be submitted by code that runs AFTER real_init returns** — but real_init never returns because it enters the job dispatch loop (at `0x804F6E510` called from `0x804F4560E`) as part of its own initialization. This is the normal Unity design: real_init sets up the job system, then enters the main loop, which blocks until the first frame event triggers job submission.

**The missing piece is the FRAME EVENT that should trigger the first job submission.** On real PS5, this would come from the display system (vblank/flip). But the game never reaches VideoOut initialization because it blocks on the job queue first.

**This is a chicken-and-egg deadlock that is BY DESIGN in Unity's architecture — the main loop waits for frame events, and frame events require VideoOut, which requires the main loop to progress past the job queue.** On real PS5, VideoOut is initialized BEFORE the main loop starts. SharpEmu must ensure VideoOut initialization happens before the job dispatch loop is entered.

### Key observation

The main thread does NOT skip any initialization steps. It runs the full real_init sequence:
1. il2cpp_init → real_init → Call #7 → Array processor → AllocateDirectMemory
2. Creates job queue (0x81), GC thread suspend/resume semaphores (0x83/0x84)
3. Creates GC thread
4. Enters job dispatch loop → blocks on WaitSema(0x81)

**The main thread never returns from real_init.** It enters the job dispatch loop AS PART OF real_init's execution. The call chain is:

```
real_init (0x804F04BA0)
  → ... initialization ...
  → call 0x804F4560E (job submit/dispatch function)
    → call 0x804F6E510 (job queue dispatch loop)
      → call 0x804F6E880 (enqueue + consume)
        → lock xadd [r14+0x90] (decrement counter)
        → counter <= 0 → WaitSema(0x81) → BLOCKS
```

### Callers of 0x804F6E510 (dispatch loop function)

5 callers, all in PRX:
- `0x804F4560E` — in real_init area (job submit)
- `0x804F4567C` — in real_init area (job submit, variant)
- `0x804FA1E2C` — in registration/callback area
- `0x804FA2142` — in registration/callback area (cleanup/shutdown)
- `0x804FA216D` — in registration/callback area (cleanup/shutdown)

The callers at `0x804F4560E` and `0x804F4567C` are in the real_init area — they are the job submission calls that happen DURING real_init. The dispatch loop at `0x804F6E510` is called from within real_init's execution, not after it.

### Unresolved NID XAKDgxcra6k

- Returns `0x80020002` (ORBIS_GEN2_ERROR_NOT_FOUND)
- Called at Import#79374
- Not in SharpEmu's HLE — unknown function
- Game continues past it (checks error code and proceeds)
- **NOT the blocker** — the game reaches WaitSema(0x81) after this NID

## Confirmed

1. **Main thread executes full real_init sequence** — CONFIRMED (Call #7, ArrayProc, AllocateDirectMemory all fire)
2. **Handle 0x81 created during real_init** — CONFIRMED (line 8437, between Call #7 and GC thread creation)
3. **Main thread blocks on WaitSema(0x81) during real_init** — CONFIRMED (line 8512, real_init never returns)
4. **No initialization step is skipped** — CONFIRMED (all expected steps fire in sequence)
5. **Unresolved NID XAKDgxcra6k is NOT the blocker** — CONFIRMED (game continues past it)
6. **The dispatch loop is called from within real_init** — CONFIRMED (caller 0x804F4560E is in real_init area)
7. **The chicken-and-egg deadlock is BY DESIGN** — the main loop waits for frame events, frame events require VideoOut, VideoOut requires the main loop to progress

## Rejected

1. **"A step is skipped during initialization"** — REJECTED. All expected steps fire.
2. **"Unresolved NID XAKDgxcra6k blocks initialization"** — REJECTED. Game continues past it.
3. **"Bootstrap job should be submitted before the dispatch loop"** — PARTIALLY REJECTED. The dispatch loop IS called from within real_init. The bootstrap job should come from a FRAME EVENT after the main loop starts, but the main loop never starts because it blocks in the dispatch loop.

## Unknown

1. **How does real PS5 break the chicken-and-egg deadlock?** On real PS5, VideoOut is likely initialized BEFORE real_init enters the job dispatch loop. SharpEmu may not initialize VideoOut early enough, or the game may expect VideoOut to already be available when it enters the dispatch loop.

2. **Does the game call sceVideoOutOpen BEFORE entering the dispatch loop?** The log shows 0 VideoOutOpen calls. Either:
   - The game expects VideoOut to be pre-initialized by the OS
   - The game calls VideoOutOpen AFTER the dispatch loop (which never happens because it blocks)
   - VideoOutOpen is called but SharpEmu doesn't log it

3. **Is there a Unity/Baselib initialization step that should submit a bootstrap job to the queue BEFORE the dispatch loop starts?** The function at `0x804F4560E` calls `0x804F6E510` (the dispatch loop) — but before that call, does it submit a job? The disassembly shows it calls `0x804FA1F90` before the dispatch loop — this might be a job submission function.
