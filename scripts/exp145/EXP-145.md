## Part 1: Emergency Workaround Tests

### 145.1 Job disable via `SHARPEMU_UNITY_NO_JOBS=1`
**Hypothesis:** Unity supports `JobsUtility.JobWorkerCount = 0` which makes the main thread execute all jobs inline. This bypasses the entire worker pool and the missing-signal deadlock.

**Implementation:**
- Add env var `SHARPEMU_UNITY_NO_JOBS=1` to SharpEmu
- When set, intercept `il2cpp_resolve_icall("Unity.Jobs.LowLevel.Unsafe.JobsUtility::ResetJobWorkerCount")` and return a stub that sets worker count to 0
- When set, intercept `il2cpp_resolve_icall("Unity.Jobs.LowLevel.Unsafe.JobsUtility::Schedule_Injected")` and return a stub that executes the job inline on the main thread

**Test:**
1. Set `SHARPEMU_UNITY_NO_JOBS=1`
2. Run Yatzi with FAST_PATH=0
3. Verify no worker threads are created (or all worker calls inline)
4. Verify main thread progresses past the dispatch loop
5. Verify first frame eventually renders

**Caveat:** This requires EXP-138 fix to be applied first (otherwise `il2cpp_resolve_icall` still returns 0).

### 145.2 Resolver bypass
**Hypothesis:** SharpEmu could provide a direct HLE-side `il2cpp_resolve_icall` implementation that maintains its own icall name → function pointer table, bypassing Yatzi's own resolver entirely.

**Implementation:**
- Intercept `il2cpp_resolve_icall` (currently delegated to Yatzi's `0x804ED8780`)
- Maintain a C# `Dictionary<string, IntPtr>` of icall name → SharpEmu HLE implementation
- For known icalls (e.g., `Unity.Jobs.LowLevel.Unsafe.JobsUtility::Schedule_Injected`), return the HLE implementation
- For unknown icalls, fall back to Yatzi's resolver

**Test:**
1. Implement HLE-side icall resolver
2. Register minimum icall set (Job System, Baselib)
3. Run Yatzi with FAST_PATH=0
4. Verify icalls resolve to real implementations
5. Verify first frame renders

### 145.3 Metadata shortcut
**Hypothesis:** SharpEmu could short-circuit the IL2CPP metadata initialization by directly populating the CodeRegistration/MetadataRegistration structures from `global-metadata.dat`, bypassing Yatzi's own init code.

**Implementation:**
- Parse `global-metadata.dat` (magic 0xFAB11BAF)
- Populate CodeRegistration at `0x8086E9000`
- Populate MetadataRegistration at `0x80885C580`
- Skip Yatzi's `il2cpp_init` real callback

**Test:**
1. Implement metadata shortcut
2. Run Yatzi with FAST_PATH=0
3. Verify metadata is accessible
4. Verify C# code can call icalls

**Caveat:** This is the most invasive workaround. Only attempt if 145.1 and 145.2 both fail.

### 145.4 Diagnostic value

These workarounds help isolate WHERE the bug is:
- If 145.1 (job disable) works → CPU/backend is fine, Unity Job System is the issue
- If 145.2 (resolver bypass) works → resolver is the issue (confirms EXP-138)
- If 145.3 (metadata shortcut) works → IL2CPP runtime init is the issue
- If NONE work → CPU/backend has a deeper bug

## Part 2: Full HLE Export Sweep

### 145.5 Sweep methodology
Scan ALL HLE export files in `src/SharpEmu.Libs/` for:
- `return 0` / `return OK` / `return ORBIS_GEN2_OK` with no real work
- `NotImplementedException`
- `// TODO` / `// FIXME` / `// stub`
- Empty method bodies
- `return -1` or wrong return values
- Missing SignalSema / Wakeup calls
